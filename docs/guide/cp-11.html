Chapter 11

파이프 한 쌍이 흘러온다

3부가 시작된다. 이제 장애물을 만든다. 그런데 이번에 쓸 코드는 새 것이 아니다. 06~07번에서 새에게 썼다가 10번에서 지워낸 그 코드를 다시 꺼내 쓴다.

읽는 시간 약 25분 · 실습 2 · 문항 2
학습 목표
  • 1빈 게임오브젝트를 껍데기로 써서 여러 물건을 하나로 묶을 수 있다.
  • 2자식의 위치가 부모 기준이라는 것을 값으로 설명할 수 있다.
  • 3새의 낙하 코드와 파이프의 이동 코드가 뭐가 같고 뭐가 다른지 말할 수 있다.
그림 11-1 · 이번 항목을 마치면 이렇게 된다
파이프 한 쌍이 오른쪽 화면 밖에서 나타나 왼쪽으로 흘러간다. 아직 하나뿐이고, 지나가면 끝이다.
11.1

새에서 지운 코드를 파이프가 쓴다

10번에서 새의 낙하 코드를 지웠다. 그 코드는 이랬다.

BirdMove.cs06~07번 상태 · 지금은 없다
transform.position += new Vector3(0f, -fallSpeed * Time.deltaTime, 0f);

파이프는 정해진 속도로 정확히 왼쪽으로 흘러가야 한다. 가속도 필요 없고 부딪혀 튕길 필요도 없다. 그러니 물리를 쓸 이유가 없다. 위 코드를 축만 바꿔 그대로 쓰면 된다.

10번에서 “물리가 항상 낫지는 않다”고 했던 이유가 여기 있다. 물리는 진짜 물체처럼 움직여야 할 때 좋고, 정해진 대로 정확히 움직여야 할 때는 직접 짜는 편이 낫다.

뭐가 같고 뭐가 다른가

코드를 보기 전에 스스로 생각해 보자. 새는 아래로 갔고, 파이프는 왼쪽으로 간다.

물어볼 것답해 보자
어느 칸을 바꾸나Vector3(?, ?, ?) 중 몇 번째 칸인가
부호는왼쪽으로 가려면 x 가 커져야 하나 작아져야 하나
Time.deltaTime 은이건 계속 일어나는 일인가, 한 번 일어나는 일인가
11.2

빈 게임오브젝트를 껍데기로

파이프는 위·아래 두 개가 한 쌍이다. 둘 사이에 새가 지나갈 틈이 있다.

두 개를 따로 움직이면 어떻게 될까? 각각에 이동 스크립트를 붙이면 굴러가긴 한다. 하지만 속도가 조금이라도 다르면 위아래가 어긋난다. 나중에 높이를 바꾸거나 지우려 할 때도 두 번씩 해야 한다.

그래서 빈 게임오브젝트를 하나 만들어 껍데기로 쓴다. 눈에 보이는 것은 아무것도 없고, 위치만 갖는 상자다.

구조역할
PipePair (빈 게임오브젝트)껍데기. 이것만 움직인다. 이동 스크립트는 여기에만 붙인다
└ PipeTop위 파이프. 눈에 보이는 것
└ PipeBottom아래 파이프. 눈에 보이는 것
부모와 자식 어떤 오브젝트를 다른 오브젝트 안으로 끌어다 놓으면 부모-자식이 된다. 부모가 움직이면 자식이 따라간다. 부모를 지우면 자식도 같이 지워진다. 이 구조는 12번의 프리팹, 20번의 판정용 오브젝트에서 계속 쓰인다.
11.3

부모 기준 좌표

자식이 되고 나면 Inspector 에 보이는 Position 의 뜻이 달라진다. 더 이상 “세상에서의 위치”가 아니라 “부모로부터 얼마나 떨어져 있는가” 가 된다.

아래에서 부모를 움직여 보자. 자식의 Inspector 값은 하나도 안 변한다.

11.0
Game 뷰부모만 움직인다
Inspector 의 Position자식은 부모 기준
오브젝트xy기준
PipePair11.00.0세상
└ PipeTop0.04.0부모
└ PipeBottom0.0−4.0부모
그림 11-2 · 부모를 움직여도 자식 값은 그대로다
초록색 숫자가 자식의 Inspector 값이다. 슬라이더를 아무리 움직여도 변하지 않는다.

이 교재를 만들면서 실제로 쟀다. 파이프가 화면을 가로지르는 7초 동안 자식의 부모 기준 위치가 움직인 거리는 0.000000 이었다.

주의 자식으로 넣기 전에 위치를 맞춰 놓았다면, 자식이 되는 순간 화면에서 위치가 튈 수 있다. 부모 기준으로 값이 다시 계산되기 때문이다. 자식으로 만든 다음에 값을 맞추자.
11.4

만들어 보자

1 · 껍데기 만들기

순서할 일
1Hierarchy 빈 곳에서 오른쪽 클릭 → Create Empty
2이름을 PipePair 로
3Position 을 (11, 0, 0) 로 — 화면 오른쪽 끝이 8.89 이므로 11 은 화면 밖이다

2 · 파이프 두 개 만들기

3D Object > Cube 로 두 개를 만들고, Hierarchy 에서 PipePair 위로 끌어다 놓아 자식으로 만든다. 그 다음 값을 맞춘다.

이름PositionScale뜻
PipeTop(0, 4, 0)(1.5, 5, 1)아래끝이 y=1.5
PipeBottom(0, −4, 0)(1.5, 5, 1)위끝이 y=−1.5

틈은 y = −1.5 ~ 1.5, 즉 3칸이다. 새가 1칸이니 넉넉하다. 계산해 보자 — 위 파이프는 중심이 4이고 세로 크기가 5이므로 아래끝이 4 − 2.5 = 1.5 다. 02번에서 바닥 윗면을 계산한 것과 같은 방식이다.

3 · 색 입히기

Assets/Materials 에 PipeMaterial 을 만들고 Base Map 을 2E7D32 로. 두 파이프에 모두 끌어다 놓는다. 바닥보다 진한 초록이라 겹쳐도 구분된다.

4 · 이동 스크립트

Assets/Scripts 에 PipeMove 를 만든다.

PipeMove.cs Assets/Scripts복사 
using UnityEngine;

public class PipeMove : MonoBehaviour
{
    public float speed = 3f;

    void Update()
    {
        transform.position += new Vector3(________________, 0f, 0f);
    }
}
가장 중요한 것 이 스크립트를 PipePair 에만 붙인다. 자식 둘에는 붙이지 않는다. 부모가 움직이면 자식은 따라간다.
정답 확인 스스로 채워 본 뒤에 펼치자
PipeMove.csAssets/Scripts
transform.position += new Vector3(-speed * Time.deltaTime, 0f, 0f);
새 (06~07번)파이프 (11번)왜
바꾸는 칸y (두 번째)x (첫 번째)아래 vs 왼쪽
부호−−둘 다 값이 작아지는 방향
deltaTime곱한다곱한다둘 다 계속 일어나는 일
+=쓴다쓴다지금 자리에서 옮긴다
거의 다 같다. 바뀐 건 “몇 번째 칸이냐” 하나뿐이다. 이게 이 항목에서 알아채야 할 것이다. 프로그래밍에서는 이렇게 이미 만든 것을 조금 바꿔 다시 쓰는 일이 훨씬 많다.
11.5

확인한다

체크리스트
Play 하면 파이프가 오른쪽 화면 밖에서 나타나 왼쪽으로 흘러간다
약 7초 뒤 화면 왼쪽 밖으로 완전히 사라진다
부모 하나만 움직이는데 위아래가 함께 간다
자식 둘의 Inspector 에 이동 스크립트가 없다
이 교재를 만들면서 잰 값 — x=11 에서 출발해 완전히 사라지기까지 6.888초 / 6.886초(두 번 측정). 그동안 자식이 부모 기준으로 움직인 거리는 0.000000, 위·아래 파이프의 x 차이도 0.000000 이었다.

문항 1 · 자식에도 스크립트를 붙이면

PipeTop 과 PipeBottom 에도 PipeMove 를 붙이면 어떻게 되나?

A똑같다. 어차피 같은 속도니까
B두 배 속도로 흘러간다
C자식은 안 움직이고 부모만 움직인다
부모가 미는 만큼 자식이 따라가고, 자식이 자기 스크립트로 또 움직인다. 그래서 자식만 두 배로 빨라져 부모(껍데기)를 앞질러 간다. 눈으로는 파이프가 너무 빨리 지나가는 것으로 보인다.

문항 2 · 부모를 움직였을 때 자식의 Inspector

PipePair 가 x=11 에서 x=0 으로 움직였다. 이때 PipeTop 의 Inspector 에 보이는 Position x 는?

A0 — 처음부터 끝까지 안 변한다
B11 에서 0 으로 같이 변한다
C−11 이 된다
자식의 Position 은 “부모로부터 얼마나 떨어져 있는가” 다. PipeTop 은 부모와 같은 x 에 있으므로 처음부터 끝까지 0 이다. 세상에서의 위치는 부모 위치 + 자식 위치 로 계산된다.
말로 설명해 보기 06~07번에서 쓴 새의 낙하 코드와 이번 파이프 코드는 뭐가 같고 뭐가 다른가? 자기 말로 설명할 수 있으면 통과다.
11.6

막혔을 때

증상원인과 해결
파이프가 오른쪽으로 간다부호를 안 붙였다. -speed 로
위아래가 어긋나며 흘러간다자식에도 PipeMove 를 붙였다. 부모에만 붙인다
시작부터 화면에 보인다PipePair 의 x 가 11 이 아니다. 화면 오른쪽 끝이 8.89 이므로 그보다 커야 밖에서 나타난다
자식으로 넣었더니 위치가 튀었다자식이 되면 값이 부모 기준으로 다시 계산된다. 자식으로 만든 다음 값을 맞추자
파이프가 너무 빠르다/느리다PipePair 의 Inspector 에서 Speed 를 바꾼다. 다만 확인이 끝나면 3 으로 되돌리자 — 13번과 16번이 이 값에 기댄다
틈이 너무 좁다/넓다파이프의 Position y 를 ±4 에서 조절한다. 멀어질수록 틈이 넓어진다
