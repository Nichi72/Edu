## 알아야 할 것

### `+=`

**"원래 값에 더해서 다시 넣어라"** 는 뜻이다.

```csharp
x += 3;        // 이 한 줄은
x = x + 3;     // 이것과 완전히 같다
```

05번에서 배운 `=` 를 생각하면 이해된다.

1. 오른쪽 `x + 3` 을 계산한다
2. 그 결과를 왼쪽 `x` 상자에 **넣는다**

⚠️ **`=` 와 `+=` 의 차이**

| | 뜻 | 예 (`x` 가 10 일 때) |
|---|---|---|
| `x = 3` | **그냥 3 을 넣는다.** 원래 값은 버린다 | `x` 는 3 |
| `x += 3` | **원래 값에 3 을 더해서 넣는다** | `x` 는 13 |

**05번은 `=` 였다. 그래서 매번 같은 자리에 다시 놨고, 결과적으로 안 움직였다.**
**이번엔 `+=` 다. 그래서 놓을 때마다 조금씩 더 내려간다.**

### 방향과 부호

좌표를 다시 떠올리자. **y 는 값이 커지면 위로 간다.**

그러면 **아래로** 가려면?

```
위로 가려면  →  y 를 크게  →  더한다  →  +
아래로 가려면 →  y 를 작게  →  뺀다   →  −
```

이 게임에서는 **아래로 내려가야 하니 y 에 마이너스**를 쓴다.

```csharp
new Vector3(0f, -fallSpeed, 0f)
```

변수 앞의 `-` 는 **"이 값의 반대"** 라는 뜻이다. `fallSpeed` 가 `0.05` 면 `-fallSpeed` 는 `-0.05` 다.

⚠️ **부호를 반대로 쓰면 새가 하늘로 날아간다.** 실수했다면 화면을 보면 바로 안다. **에러가 아니라 방향 문제다.**

### `Update()` 로 옮긴다는 것

05번에서는 `Start()` 안에 썼다. **한 번만 실행되니 한 번만 움직였다.**

이번엔 같은 코드를 `Update()` 로 옮긴다. **매 프레임 실행되니 매 프레임 조금씩 움직인다.**

> **코드는 거의 그대로인데, 어디에 두느냐로 결과가 완전히 달라진다.**
> 이게 04번에서 `Start` 와 `Update` 를 그렇게 강조한 이유다.

## 해보기

### 1. 순서부터 세운다

이번에 할 일은 이것이다.

> **새가 매 프레임 조금씩 아래로 내려간다.**

한국어로 적어보자. **두 줄이면 된다.**

```
1. ________________________________
2. ________________________________
```

> 막히면 이 둘부터 답해보자.
> - 이건 **한 번만** 할 일인가, **계속** 할 일인가?
> - 위치를 **새 값으로 갈아끼우는** 건가, **원래 값에서 조금 옮기는** 건가?

### 2. 코드 고치기

`BirdMove.cs` 를 연다. 05번 코드가 있을 것이다.

```csharp
using UnityEngine;

public class BirdMove : MonoBehaviour
{
    void ________()
    {
        float fallSpeed = 0.05f;

        transform.position ____ new Vector3(0f, ________, 0f);
    }
}
```

**빈칸 힌트**

| 빈칸 | 힌트 |
|---|---|
| 메서드 이름 | 매 프레임 실행돼야 한다. 04번의 표를 보자 |
| `transform.position` 뒤 | 갈아끼우는 게 아니라 **원래 값에서 옮긴다** |
| `Vector3` 의 두 번째 칸 | 아래로 가야 한다. **부호**를 생각하자 |

> `Vector3` 의 첫 번째 칸이 `0f` 인 이유 — 가로로는 안 움직이니 **x 는 0만큼 옮긴다** = 그대로다.
> 05번에서는 위치를 통째로 갈아끼웠으니 x 를 `-3f` 로 적어야 했지만, 이번엔 **얼마나 옮길지**를 적으므로 0 이다. **이 차이가 `=` 와 `+=` 의 차이다.**

`Ctrl + S` → Unity 로 → **Play**

새가 아래로 쭉 내려가 화면 밖으로 사라진다.

## 확인하기

- [ ] Play 하면 새가 **계속** 아래로 내려간다
- [ ] **3초 안에** 화면 아래로 완전히 사라진다
- [ ] Stop 하면 원래 자리로 돌아온다

### 매 프레임 같은 폭으로 줄어드는지 보기

Play 중에 `Bird` 의 Inspector 에서 `Position Y` 를 보자. 너무 빨라서 읽기 어렵다.

**Pause 를 쓰면 한 프레임씩 볼 수 있다.**

1. **Play** 를 누른다
2. 바로 **⏸ (Pause)** 를 누른다 — Play 버튼 오른쪽에 있다
3. **⏭ (Step)** 을 한 번씩 누르면서 Inspector 의 `Position Y` 를 적어보자

이 교재를 만들면서 실제로 재본 값이다.

| 프레임 | Position Y |
|---|---|
| 1 | −0.05 |
| 2 | −0.10 |
| 3 | −0.15 |

**매번 정확히 0.05 씩 줄어든다.** 이게 "같은 폭으로 줄어든다" 는 말의 뜻이다.

- [ ] Step 을 눌러가며 **매번 같은 폭으로 줄어드는 것**을 확인했다

## 안 되면

### 새가 하늘로 올라간다

**원인** — 부호를 반대로 썼다. `fallSpeed` 앞에 `-` 를 붙이자.

```csharp
new Vector3(0f, fallSpeed, 0f)     // 위로 올라간다
new Vector3(0f, -fallSpeed, 0f)    // 아래로 내려간다
```

**에러가 아니다.** 컴파일은 잘 되고, 그냥 방향이 반대인 것이다. 이런 건 화면을 보면 바로 안다.

### 새가 한 칸만 내려가고 멈춘다

**원인 1** — 코드가 아직 `Start()` 안에 있다. `Update()` 로 옮기자.

**원인 2** — `+=` 가 아니라 `=` 를 썼다.

`=` 는 매 프레임 **같은 자리에 다시 놓는다.** 그래서 안 움직이는 것처럼 보인다.
`+=` 는 매 프레임 **지금 자리에서 조금 더** 옮긴다.

### 새가 너무 빨라서 안 보인다 / 너무 느리다

`fallSpeed` 값을 바꿔보자. 크면 빠르고, 작으면 느리다.

⚠️ 지금은 **코드를 열어서 고쳐야** 값을 바꿀 수 있다. 불편하다.
**07번에서 이 불편함을 해결한다.**

### 3초가 넘는데요

**PC 가 느린 것이지 코드가 틀린 게 아니다.**

이 교재를 만들면서 실제로 재본 값이다. 같은 코드인데 이렇게 다르다.

| 1초에 그리는 프레임 수 | 사라지기까지 걸린 프레임 | 걸린 시간 |
|---|---|---|
| 60장 | 110 프레임 | **1.98초** |
| 30장 | 110 프레임 | **3.64초** |

**프레임 수는 110 으로 똑같은데 시간만 다르다.**

왜 이런 일이 생기는지, 그리고 **어떻게 해결하는지는 바로 다음 항목(07)에서 다룬다.** 지금은 "PC 마다 속도가 다르구나" 만 알고 넘어가자. 3초가 조금 넘어도 통과다.

## 그래도 안 되면 — 답

> 「순서부터 세운다」를 스스로 해봤다면 봐도 된다.

**순서 예시**

1. 매 프레임마다 → `Update()` 에
2. 지금 위치에서 아래로 조금 옮긴다 → `+=` 로, y 에 마이너스

**완성 코드** — `Assets/Scripts/BirdMove.cs`

```csharp
using UnityEngine;

public class BirdMove : MonoBehaviour
{
    void Update()
    {
        float fallSpeed = 0.05f;

        transform.position += new Vector3(0f, -fallSpeed, 0f);
    }
}
```

**05번에서 뭐가 바뀌었나**

```diff
-    void Start()
+    void Update()
     {
-        float newY = -1f;
+        float fallSpeed = 0.05f;
 
-        transform.position = new Vector3(-3f, newY, 0f);
+        transform.position += new Vector3(0f, -fallSpeed, 0f);
     }
```

**바뀐 곳은 세 군데다.**

| 바뀐 것 | 왜 |
|---|---|
| `Start` → `Update` | 한 번이 아니라 **계속** 해야 하니까 |
| `=` → `+=` | 갈아끼우는 게 아니라 **지금 자리에서 옮겨야** 하니까 |
| `-3f` → `0f` (x 칸) | `+=` 는 **얼마나 옮길지**를 적는다. 가로는 안 움직이니 0 |

## 더 알고 싶으면

### 왜 정확히 110 프레임인가

새는 y = 0 에서 출발한다. 화면 아래 끝은 y = −5 이고, 새의 절반 높이가 0.5 이므로
**y 가 −5.5 가 되는 순간 완전히 사라진다.**

```
내려가야 할 거리 = 5.5칸
한 프레임에 내려가는 거리 = 0.05칸

5.5 ÷ 0.05 = 110 프레임
```

실제로 재봤더니 **정확히 110 프레임**이었다. 60장짜리 PC 에서도, 30장짜리 PC 에서도 똑같이 110 프레임이다.

**프레임 수는 같은데 시간이 다르다.** 왜냐하면 1프레임에 걸리는 시간이 PC 마다 다르기 때문이다.

```
60장 PC : 110프레임 ÷ 60장 = 1.83초   (실측 1.98초)
30장 PC : 110프레임 ÷ 30장 = 3.67초   (실측 3.64초)
```

**이건 게임으로선 큰 문제다.** 좋은 PC 를 쓰는 사람은 새가 빨리 떨어지고, 느린 PC 를 쓰는 사람은 천천히 떨어진다. **같은 게임인데 난이도가 달라진다.**

**07번에서 이걸 해결한다.**
