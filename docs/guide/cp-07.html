알아야 할 것

개념

public 과 private

“이 상자를 밖에서 볼 수 있게 할까?” 를 정하는 말이다. 아무것도 안 쓰면 private 이다. 지금까지 쓴 변수들이 Inspector에 안 보였던 이유다.

실험 · public을 붙이면 어떻게 되나

눌러서 바꿔보자
지금: private 
public class BirdMove : MonoBehaviour
{
    float fallSpeed = 3f;

    void Update()
    {
        ...
    }
}
Inspector — Bird Move (Script)
칸이 하나도 없다

변수가 메서드 밖, class 안에 있어야 노출된다. Update() 안에 있으면 public을 붙여도 안 보인다.

⚠ Inspector 값이 코드보다 세다. public float fallSpeed = 3f; 의 3f는 “처음 만들 때의 기본값”일 뿐이다. 한 번 칸이 생기면 Unity는 씬에 저장된 값을 쓴다. 코드를 고쳐도 Inspector 값은 안 바뀐다.

프레임레이트 (FPS)

1초에 화면을 몇 장 그리는지다. 좋은 PC는 60장·120장, 느린 PC는 30장·20장. PC마다 다르다.

Time.deltaTime ★

직전 프레임에서 지금 프레임까지 걸린 시간(초)이다.

빠른 PC는 작고, 느린 PC는 크다. 정확히 반대로 움직인다.

실험 · fps가 바뀌면 deltaTime은 얼마가 되나

60 장
한 장에 걸리는 시간 (deltaTime)0.0167 초
초당 3칸으로 정했을 때 한 프레임 이동0.050 칸
1초 동안 총 이동3.000 칸

장수를 아무리 바꿔도 1초 동안 총 이동은 3칸에서 안 변한다. 이게 deltaTime이 하는 일의 전부다.

빈칸힌트
float 앞Inspector에 보이게 하는 말
fallSpeed 값1초에 몇 칸 갈 것인가. 06번과 같은 느낌을 내려면 0.05 × 60

⚠ 단위가 바뀐다. 06번의 0.05는 한 프레임에 갈 거리였고, 07번의 값은 1초에 갈 거리다. 값이 60배 커진 게 아니라 뜻이 달라진 것이다.

막혔을 때

Inspector에 Fall Speed 칸이 안 보인다

public을 안 붙였거나, 변수가 Update() 안에 있다. 위의 첫 번째 실험에서 두 경우를 다 눌러보자.

코드의 숫자를 고쳤는데 안 바뀐다

Inspector 값이 코드보다 세다. 값은 Inspector에서 바꾸자. 굳이 코드 기본값으로 되돌리려면 Bird Move (Script) 오른쪽 점 세 개(⋮) → Reset.

새가 너무 느리다

값을 0.05 그대로 뒀다. 단위가 바뀌었다. 06번과 같은 느낌을 내려면 0.05 × 60 = 3.

targetFrameRate를 바꿔도 안 느려진다

vSync가 켜져 있으면 targetFrameRate가 무시된다. Edit > Project Settings > Quality에서 V Sync Count를 Don't Sync로. (이 교재의 프로젝트는 처음부터 꺼져 있다)

답

완성 코드 보기 스스로 해본 뒤에 열자 
using UnityEngine;

public class BirdMove : MonoBehaviour
{
    public float fallSpeed = 3f;

    void Update()
    {
        transform.position += new Vector3(0f, -fallSpeed * Time.deltaTime, 0f);
    }
}

06번에서 바뀐 곳은 세 군데다.

바뀐 것왜
Update 안 → 클래스 바로 밑Inspector에 노출하려면 메서드 밖이어야 한다
public 추가밖에서 볼 수 있게
* Time.deltaTime“1초에 갈 거리”에 이번 프레임 시간을 곱해 실제 이동량을 구한다

더 알고 싶으면

Unity에서 실제로 재본 값

이 교재를 만들면서 진짜 Unity로 측정한 값이다. 위 실험과 같은 이야기다.

방식빠를 때느릴 때차이
06번 (곱하기 없음)1.98초 60fps3.64초 30fps1.653초
07번 (deltaTime)1.84초 60fps1.93초 10fps0.086초

07번 쪽은 10fps로 훨씬 더 극단적인 조건인데도 차이가 20분의 1이다.

그럼 완전히 똑같아지나

아니다. 0.086초가 남았다. 10fps에서는 한 프레임에 0.34칸씩 뛴다. 사라지는 지점을 정확히 밟지 못하고 넘어가버린다. 그 초과분이 오차로 남는다. 그래서 기준이 “완전히 같다”가 아니라 “0.3초 이내”인 것이다.
