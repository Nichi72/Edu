Chapter 07

숫자를 코드 밖에서 만지고,
어느 PC에서나 같게 만든다

06번에서 남긴 불편이 두 가지였다. 속도를 바꾸려면 코드를 열어야 하고, PC 성능에 따라 낙하 속도가 달라진다. 둘 다 여기서 해결한다.

읽는 시간 약 25분 · 실습 3 · 문항 2
학습 목표
  • 1public을 붙여 값을 Inspector에 노출하고, 코드를 열지 않고 바꿀 수 있다.
  • 2Time.deltaTime이 무엇을 재는 값인지 말할 수 있다.
  • 3왜 곱해야 어느 PC에서나 같아지는지 자기 말로 설명할 수 있다.
먼저 06번까지 끝냈고, =가 “오른쪽 값을 왼쪽에 넣어라”라는 뜻임을 말할 수 있어야 한다. 그렇지 않으면 05번으로 돌아가자.
7.1

값을 코드 밖으로 꺼낸다

public과 private은 “이 상자를 밖에서 볼 수 있게 할까”를 정하는 말이다. 아무것도 안 쓰면 private이고, 그래서 지금까지 쓴 변수들이 Inspector에 안 보였다.

아래에서 직접 붙였다 떼어 보자. 변수가 메서드 밖, class 안에 있어야 노출된다는 점도 같이 확인된다.

지금은 private — Inspector에 아무 칸도 없다
BirdMove.cs Assets/Scripts 
public class BirdMove : MonoBehaviour
{
    float fallSpeed = 3f;

    void Update() { ... }
}
Inspector — Bird Move (Script)
칸이 하나도 없다
주의 한 번 칸이 생기면 Inspector 값이 코드보다 세다. public float fallSpeed = 3f;의 3f는 “처음 만들 때의 기본값”일 뿐이고, 그 뒤로 Unity는 씬에 저장된 값을 쓴다. 코드를 고쳐도 Inspector 값은 안 바뀐다.
7.2

프레임마다 걸리는 시간이 다르다

게임 화면은 아주 빠르게 그려지는 그림 여러 장이고, 1초에 몇 장을 그리는지를 프레임레이트라 한다. 좋은 PC는 60장·120장, 느린 PC는 30장·20장. PC마다 다르고 상황에 따라서도 달라진다.

Time.deltaTime은 직전 프레임에서 지금 프레임까지 걸린 시간(초)이다. 빠른 PC에서는 작고, 느린 PC에서는 크다. 정확히 반대로 움직인다.

60장
재는 값결과
Time.deltaTime0.0167초
초당 3칸일 때 한 프레임 이동0.050칸
1초 동안 총 이동3.000칸

장수를 아무리 바꿔도 1초 동안 총 이동은 3칸에서 안 변한다. 이게 deltaTime이 하는 일의 전부다.

7.3

곱하기 하나가 만드는 차이

말로 듣는 것보다 한 번 보는 게 빠르다. 같은 새 두 마리를 같은 장수로 떨어뜨린다. 왼쪽은 06번 방식이고, 오른쪽은 deltaTime을 곱한 07번 방식이다.

60장
06번 방식position += fallSpeed
걸린 시간—
07번 방식position += fallSpeed * deltaTime
걸린 시간—
그림 7-1 · 곱하기 유무에 따른 낙하 시간
화면 세로 −5 ~ 5칸, 새 크기 1칸. y가 −5.5가 되면 완전히 사라진 것으로 본다.
장수06번 방식07번 방식

왼쪽은 장수에 따라 몇 배씩 달라진다. 오른쪽은 거의 안 변한다.

Unity에서 실제로 재본 값

이 교재를 만들면서 진짜 Unity로 측정했다. 위 실험과 같은 이야기다.

방식빠를 때느릴 때차이
06번1.98초 60fps3.64초 30fps1.653초
07번1.84초 60fps1.93초 10fps0.086초

07번 쪽은 10fps라는 훨씬 극단적인 조건인데도 차이가 20분의 1이다.

7.4

코드를 고친다

고칠 곳은 세 군데다. 빈칸을 채워 보자.

BirdMove.cs Assets/Scripts 복사 
using UnityEngine;

public class BirdMove : MonoBehaviour
{
    ______ float fallSpeed = ____;

    void Update()
    {
        transform.position += new Vector3(0f, -fallSpeed * ______________, 0f);
    }
}
빈칸힌트
float 앞Inspector에 보이게 하는 말
fallSpeed 값1초에 몇 칸 갈 것인가. 06번과 같은 느낌을 내려면 0.05 × 60
곱하기 뒤이번 프레임이 걸린 시간. Time.으로 시작한다
주의 단위가 바뀐다. 06번의 0.05는 한 프레임에 갈 거리였고, 07번의 값은 1초에 갈 거리다. 값이 60배 커진 게 아니라 뜻이 달라진 것이다.
정답 확인 스스로 채워 본 뒤에 펼치자
BirdMove.cs Assets/Scripts 
using UnityEngine;

public class BirdMove : MonoBehaviour
{
    public float fallSpeed = 3f;

    void Update()
    {
        transform.position += new Vector3(0f, -fallSpeed * Time.deltaTime, 0f);
    }
}
바뀐 것왜
Update 밖으로Inspector에 노출하려면 메서드 밖, class 안이어야 한다
public 추가밖에서 볼 수 있게
* Time.deltaTime“1초에 갈 거리”에 이번 프레임 시간을 곱해 실제 이동량을 구한다
7.5

확인한다

체크리스트
Bird의 Inspector에 Fall Speed 칸이 보인다
코드를 열지 않고 Inspector에서 낙하 속도를 바꿀 수 있다
targetFrameRate 10과 60에서 사라진 시각의 차이가 0.3초 이내다
실험용 코드(Start 덩어리, Debug.Log)를 지웠다

문항 1 · 곱하지 않으면 어떻게 되나

Time.deltaTime을 빼고 fallSpeed만 더하면, 120장을 그리는 PC에서는 60장짜리 PC에 비해 새가 어떻게 되나?

A똑같이 떨어진다
B두 배 빨리 떨어진다
C두 배 느리게 떨어진다
한 프레임에 갈 거리를 정해 두었기 때문이다. 장수가 두 배면 같은 시간에 두 배 많이 움직인다. deltaTime을 곱하면 프레임이 짧아진 만큼 한 번에 가는 거리도 줄어들어 상쇄된다.

문항 2 · 점프에도 곱해야 하나

스페이스를 누르면 한 번 위로 튀는 코드를 쓴다고 하자. 여기에도 Time.deltaTime을 곱해야 할까?

A곱해야 한다. 움직임이니까
B곱하지 않는다. 한 번만 일어나는 일이니까
기준은 “계속 일어나는 일인가, 한 번 일어나는 일인가”다. 낙하는 매 프레임 조금씩 일어나므로 곱한다. 점프는 눌렀을 때 한 번만 일어나므로 곱하지 않는다. 곱하면 0.017을 곱한 셈이 되어 거의 안 움직인다. 08번에서 다시 다룬다.
말로 설명해 보기 왜 Time.deltaTime을 곱할까? 곱하지 않으면 무슨 일이 생길까? 자기 말로 설명할 수 있으면 통과다. 못 하면 넘어가지 말자. 앞으로 움직임이 나올 때마다 이 곱하기가 나온다.
7.6

막혔을 때

증상원인과 해결
Inspector에 칸이 없다public을 안 붙였거나, 변수가 Update() 안에 있다. 7.1의 실험에서 두 경우를 다 눌러 보자
코드 숫자를 고쳐도 그대로다Inspector 값이 코드보다 세다. 값은 Inspector에서 바꾸자. 코드 기본값으로 되돌리려면 Bird Move (Script) 오른쪽 점 세 개 → Reset
새가 너무 느리다값을 0.05 그대로 뒀다. 단위가 바뀌었으니 0.05 × 60 = 3
targetFrameRate가 안 먹는다vSync가 켜져 있으면 무시된다. Edit > Project Settings > Quality에서 V Sync Count를 Don't Sync로

완전히 똑같아지지는 않는다

실측에서 0.086초가 남았다. 10fps에서는 한 프레임에 0.34칸씩 뛰기 때문에 사라지는 지점을 정확히 밟지 못하고 넘어가 버린다. 그 초과분이 오차로 남는다. 그래서 기준이 “완전히 같다”가 아니라 0.3초 이내인 것이다.

움직임을 다루는 곳마다 Time.deltaTime을 곱한다. 11번 파이프 이동, 13번 시간 재기에서 다시 만난다. 13번에서는 곱하는 게 아니라 더하는 데 쓴다.
