Chapter 10

낙하를 직접 짠 코드에서
물리로 넘긴다

지금까지 새는 일정한 속도로 떨어지고, 스페이스를 누르면 순간이동하듯 위로 뛰었다. 진짜 물체는 그렇게 움직이지 않는다. 이번에는 그 일을 Unity 의 물리에 맡긴다.

읽는 시간 약 30분 · 실습 3 · 문항 2
학습 목표
  • 1Rigidbody 를 붙여 중력을 Unity 에 맡길 수 있다.
  • 2Constraints 로 원하지 않는 회전과 이동을 막을 수 있다.
  • 3등속과 가속의 차이를 화면과 숫자로 구분할 수 있다.
  • 4손으로 짠 낙하와 물리 중 무엇이 더 나은지, 왜 그런지 설명할 수 있다.
이번 항목의 특별한 점 지금까지는 코드를 더했다. 이번에는 지워낸다. 05번부터 공들여 만든 낙하 코드가 통째로 사라지고 그 자리를 물리가 대신한다. 아깝게 느껴지겠지만, 그 코드를 직접 짜봤기 때문에 물리가 무엇을 대신해 주는지 알 수 있다.
10.1

손으로 만든 낙하의 한계

09번까지 만든 낙하는 이랬다.

BirdMove.cs09번 상태
transform.position += new Vector3(0f, -fallSpeed * Time.deltaTime, 0f);

이 코드는 1초에 3칸씩, 처음부터 끝까지 같은 속도로 내려간다. 이것을 등속이라고 한다.

그런데 진짜 물체는 그렇지 않다. 손에서 놓은 공은 처음엔 천천히, 갈수록 빨라진다. 이것을 가속이라고 한다.

점프도 마찬가지였다. 스페이스를 누르면 순간이동하듯 1.5칸 위로 튀어 오르고, 곧바로 같은 속도로 내려왔다. 진짜 점프는 올라가다가 점점 느려지고, 잠깐 멈췄다가, 점점 빨라지며 떨어진다.

왜 직접 짰나 처음부터 물리를 쓰지 않은 이유가 있다. +=, Time.deltaTime, 부호, if — 05번부터 09번까지 배운 것들은 물리를 쓰든 안 쓰든 계속 필요한 도구다. 물리부터 배웠다면 그 도구들을 쓸 일이 없었을 것이다.
10.2

Rigidbody 를 붙인다

Rigidbody 는 "이 물체를 물리 법칙에 따라 움직여라" 라고 Unity 에게 맡기는 컴포넌트다. 붙이는 순간 중력이 적용되고, 부딪히면 멈춘다.

붙이는 방법

순서할 일
1Hierarchy 에서 Bird 를 클릭
2Inspector 맨 아래 Add Component 클릭
3Rigidbody 를 검색해서 추가 (Rigidbody 2D 가 아니다)

Constraints — 원하지 않는 움직임을 막는다

물리를 켜면 Unity 는 모든 방향으로 움직이려 한다. 우리 게임은 옆에서 보는 2D 라서 그중 일부는 방해가 된다.

막아야 할 것왜
회전 (Freeze Rotation X·Y·Z)부딪히면 새가 빙글빙글 돈다. 옆에서 보는 게임에서는 이상하다
Z 이동 (Freeze Position Z)화면 안쪽·바깥쪽으로 밀려나면 카메라에서 크기가 달라지거나 사라진다

Inspector 의 Rigidbody 안에서 Constraints 를 펼치고, Freeze Position 의 Z 와 Freeze Rotation 의 X·Y·Z 를 모두 체크한다.

Interpolate 같은 Rigidbody 안의 Interpolation 을 Interpolate 로 바꾸면 움직임이 한결 부드러워진다. 물리 계산은 화면 갱신과 주기가 달라서, 그 사이를 메워 주는 기능이다.
10.3

등속과 가속의 차이

말로는 잘 와닿지 않는다. 같은 높이에서 두 마리를 동시에 떨어뜨려 보자. 왼쪽은 09번까지의 방식(등속), 오른쪽은 물리(가속)다.

점프는 왼쪽이 순간이동, 오른쪽이 속도 주기다
09번까지 — 등속position += 속도 * deltaTime
속도0.00
10번 — 물리(가속)Rigidbody 가 알아서
속도0.00
그림 10-1 · 등속과 가속
왼쪽 속도는 3.00 에서 변하지 않는다. 오른쪽은 계속 커진다. 점프를 눌러 보면 차이가 더 분명하다.

Unity 에서 실제로 잰 값

물리를 켠 뒤 y = 4 에서 떨어뜨리며 0.1초마다 기록한 값이다.

시각높이 y그동안 내려간 폭속도
0.51초2.760.486−4.905
0.60초2.260.493−5.886
0.71초1.580.688−6.867
0.81초0.860.713−7.848
0.90초0.050.813−8.829
1.00초−0.840.888−9.810
1.10초−1.861.019−10.791
1.21초−3.101.240−11.772

속도가 0.1초마다 정확히 0.981 씩 커진다. 지구 중력이 초당 9.81 이니까, 0.1초면 0.981 이다. Unity 가 진짜 중력을 그대로 쓰고 있다는 뜻이다.

내려간 폭도 0.486 → 0.493 → 0.688 → … → 1.240 으로 계속 커진다. 이게 가속이고, 화면에서는 포물선으로 보인다.

09번까지의 방식이었다면 이 표의 “내려간 폭” 칸이 처음부터 끝까지 0.300 으로 똑같았을 것이다.
10.4

코드를 고친다

이번에는 지우는 것이 더 많다. 낙하 코드는 통째로 사라지고, 점프는 “순간이동”에서 “속도 주기”로 바뀐다.

BirdMove.cs Assets/Scripts복사 
using UnityEngine;
using UnityEngine.InputSystem;

public class BirdMove : MonoBehaviour
{
    public float jumpPower = 5f;

    Rigidbody rb;
    bool isDead = false;

    void Start()
    {
        rb = __________________;
    }

    void Update()
    {
        if (!isDead)
        {
            if (Keyboard.current.spaceKey.wasPressedThisFrame)
            {
                rb.______________ = new Vector3(0f, jumpPower, 0f);
            }

            if (transform.position.y >= 4.5f || transform.position.y <= -3.5f)
            {
                isDead = true;
                Debug.Log("Dead");
            }
        }
    }
}
빈칸힌트
rb = 내가 붙어 있는 오브젝트에서 컴포넌트 하나를 찾아온다. GetComponent 로 시작하고 꺾쇠 안에 타입 이름을 쓴다
rb. 뒤물체의 속도를 담는 칸. linear 로 시작한다

사라진 것

지운 것이제 누가 하나
fallSpeed 변수Rigidbody 의 중력
낙하 transform.position += 줄Rigidbody 의 중력
천장 보정 if필요 없어졌다. 물리로는 조금씩 올라가서 훌쩍 넘어가지 않는다
주의 이제 transform.position 으로 새를 옮기면 안 된다. 물리가 위치를 관리하고 있어서 서로 싸운다. 옮겨야 한다면 rb.position 을 쓴다. — 이 교재를 만들면서 실제로 걸렸던 부분이다. transform.position 으로 새를 옮겼더니 물리가 곧바로 되돌려 놓았다.
정답 확인 스스로 채워 본 뒤에 펼치자

줄뜻
GetComponent<Rigidbody>()“내가 붙어 있는 오브젝트에서 Rigidbody 를 찾아와라”. 매 프레임 찾으면 낭비이므로 Start() 에서 한 번만 찾아 rb 에 담아 둔다
rb.linearVelocity = …“지금 속도를 이 값으로 바꿔라”. 위로 5 를 넣으면 위로 솟았다가 중력에 의해 자연스럽게 되돌아온다
왜 += 가 아니라 = 인가 += 를 쓰면 빠르게 연타할수록 속도가 계속 쌓여 새가 로켓처럼 날아간다. = 로 덮어써야 언제 눌러도 같은 높이로 뛴다.
10.5

확인한다

체크리스트
새가 회전하지 않는다 — Play 중 Inspector 의 Rotation 이 (0, 0, 0) 에서 안 변한다
Position Z 가 0 에서 변하지 않는다
낙하가 등속이 아니라 점점 빨라진다
스페이스를 누르면 위로 튀었다가 부드럽게 내려온다
바닥에 얹힌 뒤 덜덜 떨지 않는다
이 교재를 만들면서 잰 값 — 바닥에 안착한 뒤 2355 프레임 동안 y 가 −3.50000 에서 한 번도 변하지 않았다. 회전 이탈 0.0000도, z 이탈 0.0000.

문항 1 · 점프에 = 를 쓰는 이유

rb.linearVelocity += new Vector3(0f, jumpPower, 0f); 처럼 += 를 쓰면 어떻게 되나?

A똑같다. 어차피 속도를 주는 것이니까
B연타하면 속도가 쌓여 새가 로켓처럼 날아간다
C점프가 아예 안 된다
+= 는 원래 속도에 더한다. 이미 위로 5 로 올라가는 중에 또 누르면 10 이 된다. = 로 덮어써야 언제 눌러도 같은 높이로 뛴다. 06번에서 배운 = 와 += 의 차이가 여기서 다시 나온다.

문항 2 · 무엇이 더 나은가

손으로 짠 낙하와 물리 중 이 게임에는 무엇이 낫나?

A손으로 짠 쪽. 코드를 내가 다 아니까
B물리 쪽. 가속·충돌 같은 걸 직접 안 짜도 된다
C둘이 완전히 같다
다만 항상 물리가 낫지는 않다. 물리는 가속·충돌·마찰을 전부 알아서 해주는 대신, 내가 원하는 대로 정확히 움직이게 만들기는 더 어렵다. 이 게임처럼 “진짜 물체처럼” 움직여야 하는 경우에는 물리가 낫고, 정해진 경로를 정확히 따라가야 하는 경우에는 직접 짜는 편이 낫다. 파이프는 11번에서 직접 짜서 움직인다.
말로 설명해 보기 손으로 짠 낙하와 물리 중 무엇이 더 나은가? 왜 그런가? 자기 말로 설명할 수 있으면 통과다.
10.6

막혔을 때

증상원인과 해결
NullReferenceException 이 뜬다Rigidbody 를 안 붙였다. GetComponent<Rigidbody>() 가 못 찾아서 rb 가 비어 있는 것이다. Inspector 에서 Add Component 로 붙이자. “있어야 할 게 없다”는 뜻이니 앞으로도 이 에러가 뜨면 “뭘 빠뜨렸지?” 부터 생각하자
새가 빙글빙글 돈다Constraints 의 Freeze Rotation X·Y·Z 를 체크하지 않았다
새가 점점 작아지거나 사라진다Z 축으로 밀려난 것이다. Freeze Position 의 Z 를 체크하자
바닥을 뚫고 내려간다Ground 에 Box Collider 가 있는지 확인. 3D Object 로 만들었다면 처음부터 붙어 있다
연타하면 로켓처럼 날아간다+= 를 썼다. = 로 덮어쓰자
코드로 위치를 바꿨는데 안 먹는다Rigidbody 가 붙으면 물리가 위치를 관리한다. transform.position 대신 rb.position 을 쓰자
스페이스를 눌러도 반응이 없다Game 뷰를 한 번 클릭하자. 키 입력은 선택된 창으로 간다

11번 예고

새는 이제 물리로 움직인다. 그런데 파이프는 물리로 움직이지 않는다. 파이프는 정해진 속도로 정확히 왼쪽으로 흘러가야 하기 때문이다. 11번에서는 06~07번에서 썼던 그 이동 코드를 다시 꺼내 쓴다. 새에서 지워낸 코드가 파이프에서 살아난다.
