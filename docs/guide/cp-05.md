## 알아야 할 것

### 변수 (Variable)

**값을 담아두고 이름을 붙여둔 상자**다.

> **비유** — 이름표가 붙은 서랍. `newY` 라고 적힌 서랍에 `-1` 을 넣어두는 것이다.

왜 그냥 숫자를 안 쓰고 상자에 담을까? **이름이 있으면 무슨 뜻인지 알 수 있기 때문**이다.

```csharp
transform.position = new Vector3(-3f, -1f, 0f);   // -1 이 뭐지?
```
```csharp
float newY = -1f;                                  // 아, 새로운 y 값이구나
transform.position = new Vector3(-3f, newY, 0f);
```

### 자료형 (Type) 과 `float`

상자에는 **무엇을 담을지 미리 정해야** 한다. 그게 자료형이다.

| 자료형 | 담는 것 | 예 |
|---|---|---|
| `float` | **소수점이 있는 숫자** | `-1.5`, `0.02`, `3` |
| `int` | 소수점 없는 정수 | `5`, `-2` (20번에서 쓴다) |
| `bool` | 참/거짓 | (09번에서 쓴다) |

게임에서 위치·속도는 거의 다 소수라서 **`float` 을 가장 많이 쓴다.**

### 숫자 뒤의 `f`

```csharp
float newY = -1f;
```

`-1` 뒤에 붙은 **`f` 는 "이건 float 이다" 라는 표시**다.

⚠️ **안 붙이면 에러가 난다.** C# 은 `-1.0` 을 기본적으로 `double`(더 큰 소수 상자)로 보기 때문에, `float` 상자에 넣으려면 `f` 를 붙여 알려줘야 한다.

**규칙: 숫자를 `float` 에 넣을 땐 뒤에 `f` 를 붙인다.** 앞으로 계속 나온다.

### `Vector3`

**숫자 세 개(x, y, z)를 한 묶음으로 담는 상자**다.

> **비유** — 주소. "3동 501호" 처럼 여러 숫자가 모여야 한 위치가 된다.

위치·방향·크기처럼 **세 방향이 한 세트인 것**은 전부 `Vector3` 로 다룬다.

### `new`

**"새로 하나 만들어라"** 는 뜻이다.

```csharp
new Vector3(-3f, -1f, 0f)
```

이건 "x 가 −3, y 가 −1, z 가 0 인 `Vector3` 를 **새로 하나 만들어라**" 는 말이다.

지금은 **`Vector3` 를 만들 때는 앞에 `new` 를 붙인다** 정도로 외워도 된다.

### `transform.position`

**그 게임오브젝트의 위치**다. Inspector 의 `Transform > Position` 칸과 **같은 것**이다.

- `transform` — 내가 붙어 있는 게임오브젝트의 Transform 컴포넌트
- `.position` — 그중 위치

**코드에서 이 값을 바꾸면 Inspector 의 숫자가 바뀌고, 화면에서 물건이 움직인다.**

### `=` 는 "같다" 가 아니다 ★

**이번 항목에서 가장 중요한 내용이다.**

수학에서 `=` 는 **"양쪽이 같다"** 는 뜻이다. 하지만 프로그래밍에서 `=` 는 다르다.

> **프로그래밍의 `=` 는 "오른쪽 값을 왼쪽 상자에 넣어라" 는 명령이다.**

방향이 있다. **오른쪽 → 왼쪽.**

```csharp
transform.position = new Vector3(-3f, -1f, 0f);
```

이건 "위치와 저 Vector3 가 같다" 가 아니라 **"저 Vector3 를 만들어서 위치 상자에 넣어라"** 는 명령이다.

**증거** — 나중에 이런 코드를 쓰게 된다.

```csharp
score = score + 1;
```

수학이라면 양변에서 `score` 를 지우면 `0 = 1` 이 된다. **말이 안 된다.**
하지만 "오른쪽을 계산해서(`score` 에 1 을 더해서) 왼쪽 상자에 넣어라" 로 읽으면 **완벽히 말이 된다.**

⚠️ 이걸 "같다" 로 읽는 습관이 남아 있으면 **06번부터 코드가 하나도 이해되지 않는다.**

### Play 와 Stop — 왜 원래대로 돌아오나

Play 중에 새가 내려갔는데, Stop 을 누르면 **원래 자리로 돌아온다.**

**Unity 는 Play 를 누른 순간의 씬 상태를 기억해뒀다가, Stop 할 때 그대로 되돌린다.**

> **비유** — 연습 무대. 마음껏 어질러도 연습이 끝나면 원위치된다.

⚠️ **아주 중요** — **Play 중에 Inspector 에서 값을 바꿔도 Stop 하면 사라진다.**
계속 남기고 싶은 값은 **반드시 Stop 상태에서** 바꿔야 한다. 이걸 모르면 "분명히 바꿨는데 왜 없어졌지?" 로 한참 헤맨다.

## 해보기

### 1. 순서부터 세운다

이번에 할 일은 이것이다.

> **Play 를 누르면 새가 딱 한 번 아래로 한 칸 내려간다.**

한국어로 적어보자. **두 줄이면 된다.**

```
1. ________________________________
2. ________________________________
```

> 막히면 이것부터 답해보자 — **이 일은 "한 번만" 할 일인가, "계속" 할 일인가?**
> 답이 정해지면 `Start()` 와 `Update()` 중 어디에 쓸지도 정해진다.

### 2. 코드 고치기

`BirdMove.cs` 를 연다. 04번에서 쓴 코드가 있을 것이다.

`Update()` 덩어리는 **통째로 지운다.** 이제 로그는 필요 없다.
`Start()` 안의 `Debug.Log` 도 지우고 아래처럼 채운다.

```csharp
using UnityEngine;

public class BirdMove : MonoBehaviour
{
    void Start()
    {
        float newY = ________;

        transform.position = new Vector3(________, ________, ________);
    }
}
```

**빈칸 힌트**

| 빈칸 | 힌트 |
|---|---|
| `newY` 에 넣을 값 | 새는 지금 y = 0 에 있다. **한 칸 아래**는 얼마인가? `f` 를 잊지 말자 |
| `Vector3` 의 첫 번째 | x. **가로는 안 움직인다.** 지금 있는 자리 그대로 |
| `Vector3` 의 두 번째 | y. 방금 만든 상자 이름을 그대로 쓴다 |
| `Vector3` 의 세 번째 | z. 옆에서 보는 게임이라 계속 0 |

> `Bird` 의 Inspector 에서 현재 Position 을 보면 x 값을 알 수 있다.

### 3. 저장하고 Play

1. `Ctrl + S` 로 코드 저장
2. Unity 로 돌아와 컴파일이 끝날 때까지 기다린다
3. **Play** 를 누른다
4. 잠시 보다가 **Stop**

## 안 되면

### 새가 안 움직인다

**원인 1** — 코드를 저장 안 했다. 코드 편집기에서 `Ctrl + S`.

**원인 2** — `Start()` 가 아니라 다른 곳에 썼다.

**원인 3** — 컴파일 에러가 있다. Console 의 빨간 줄부터 확인하자.

### `CS0664` 에러가 난다

```
CS0664: 리터럴 형식 double을 float 형식으로 암시적으로 변환할 수 없습니다
```

**원인** — 숫자 뒤에 **`f` 를 안 붙였다.**

```csharp
float newY = -1;      // 에러
float newY = -1f;     // 정상
```

`Vector3` 안의 숫자도 마찬가지다. `new Vector3(-3, -1, 0)` 이 아니라 `new Vector3(-3f, -1f, 0f)`.

### 새가 엉뚱한 곳으로 간다

**원인** — `Vector3` 안 숫자의 **순서**를 헷갈렸다. 순서는 언제나 **(x, y, z)** 다.

- 좌우로 갔다 → 첫 번째 칸(x)을 건드렸다
- 사라졌다 → 세 번째 칸(z)을 건드려 카메라 뒤로 갔을 수 있다

### 새가 계속 아래로 내려간다

**원인** — 코드를 `Update()` 안에 썼다.

`Update()` 는 매 프레임 실행되므로 위치를 계속 다시 넣는다. 다만 **같은 값**을 넣으니 실제로는 한 칸에 멈춰 있을 것이다. `Start()` 로 옮기자.

> 계속 **내려가게** 만드는 건 다음 항목(06)에서 한다.

### Stop 했더니 원래대로 돌아왔다 — 버그인가?

**정상이다.** Unity 는 Play 전 상태를 기억했다가 Stop 할 때 되돌린다.

⚠️ 그래서 **Play 중에 Inspector 값을 바꾸면 Stop 할 때 사라진다.** 값을 남기려면 Stop 상태에서 바꾸자.

## 더 알고 싶으면

### 왜 `-3f` 를 그대로 적었나

새의 지금 x 값이 −3 이라서 **가로는 그대로 두려고** 같은 값을 적었다.

여기엔 문제가 하나 있다. **Inspector 에서 새를 다른 x 로 옮기면 코드가 그 값을 −3 으로 되돌려버린다.**
지금은 넘어가고, **07번에서 "숫자를 코드 밖에서 만지는 법"** 을 배우면서 이런 문제를 다룬다.
