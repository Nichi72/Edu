### 게임오브젝트 (GameObject)
**처음**: cp-02

씬 위에 놓이는 물건 하나하나. 새도 바닥도 카메라도 전부 게임오브젝트다.

> **비유** — 무대 위의 배우와 소품

⚠️ 게임오브젝트 자체는 **아무 능력도 없는 빈 껍데기**다. 능력은 전부 컴포넌트가 준다.

### 씬 (Scene)
**처음**: cp-02

게임의 한 화면을 담아두는 파일.

> **비유** — 연극의 무대 하나. 배우와 소품을 올려두고 그 상태를 통째로 저장한다

⚠️ 씬 탭 이름 옆에 별표(`*`)가 있으면 **아직 저장 안 된 것**이다.

### 좌표 (x, y, z)
**처음**: cp-02

위치를 숫자로 말하는 방법. **x** 가로(클수록 오른쪽) / **y** 세로(클수록 위) / **z** 깊이.

우리 게임은 옆에서 보는 2D 라 **z 는 계속 0** 이다.

⚠️ 1칸이 몇 cm 인지는 정해져 있지 않다. **우리가 정한다.** 이 게임은 새 한 마리가 1칸이다.

### 컴포넌트 (Component)
**처음**: cp-02

게임오브젝트에 붙이는 능력 하나. Transform, Mesh Renderer, Box Collider 등.

> **비유** — 배우에게 입히는 옷과 소품

**게임오브젝트 = 껍데기 + 컴포넌트 여러 개.** 이 문장이 Unity 의 거의 전부다.

### 화면 비율 (Aspect)

### `+=`
**처음**: cp-06

**"원래 값에 더해서 다시 넣어라".** `x += 3` 은 `x = x + 3` 과 **완전히 같다.**

| | 뜻 | `x` 가 10 일 때 |
|---|---|---|
| `x = 3` | 그냥 3 을 넣는다. 원래 값은 버린다 | 3 |
| `x += 3` | 원래 값에 3 을 더해서 넣는다 | 13 |

`=` 로는 매 프레임 같은 자리에 다시 놓아 안 움직이는 것처럼 보이고,
`+=` 로는 놓을 때마다 조금씩 옮겨간다.

### 입력 감지 / KeyCode
**처음**: cp-08

키보드가 눌렸는지 물어보는 것. `Input.GetKeyDown(KeyCode.Space)`

- `Input` — 입력 담당 Unity 기능
- `KeyCode.Space` — 스페이스바

**참 아니면 거짓**을 내놓으므로 `if` 조건 자리에 그대로 들어간다.

⚠️ 키 입력은 **지금 선택된 창**으로 간다. **Game 뷰를 한 번 클릭**해두지 않으면 반응이 없다.
(가장 흔한 막힘)

### 프레임레이트 (FPS)
**처음**: cp-07

1초에 화면을 몇 장 그리는지. `frames per second`.
좋은 PC 는 60·120·144장, 느린 PC 는 30·20장. **PC 마다 다르고 상황에 따라도 달라진다.**

### GetKeyDown / GetKey / GetKeyUp  ★
**처음**: cp-08

| | 언제 참 | 3초간 꾹 누르면 |
|---|---|---|
| `GetKeyDown` | **누르는 순간 한 번** | 1번 |
| `GetKey` | 누르고 있는 동안 계속 | 약 180번 |
| `GetKeyUp` | 떼는 순간 한 번 | 1번 |

> **비유** — `GetKeyDown` 은 **초인종**(누르는 순간 한 번), `GetKey` 는 **손전등 버튼**(누르는 동안 계속)

### if
**처음**: cp-08

**"만약 ~라면 이걸 해라".** 조건이 참이면 중괄호 안을 실행하고, 거짓이면 통째로 건너뛴다.

> **비유** — 갈림길

⚠️ **`if` 뒤에 세미콜론을 붙이면 안 된다.** `if (조건);` 이면 거기서 문장이 끝나고
아래 중괄호가 **조건과 상관없이 매번 실행**된다. **컴파일 에러가 안 나서** 화면을 봐야 안다.

### Pause / Step
**처음**: cp-06

Play 버튼 오른쪽의 **⏸ Pause** 와 **⏭ Step**.

### Play / Stop 이 원래대로 돌아가는 이유
**처음**: cp-05

Unity 는 **Play 를 누른 순간의 씬 상태를 기억해뒀다가 Stop 할 때 그대로 되돌린다.**

> **비유** — 연습 무대. 마음껏 어질러도 연습이 끝나면 원위치된다

⚠️ **Play 중에 Inspector 값을 바꿔도 Stop 하면 사라진다.**
남기고 싶은 값은 **반드시 Stop 상태에서** 바꾼다. 모르면 "분명 바꿨는데" 로 한참 헤맨다.

### Inspector 창
**처음**: cp-02

### public / private
**처음**: cp-07

"이 상자를 밖에서 볼 수 있게 할까?" 를 정하는 말.

| | Inspector 에 |
|---|---|
| `public` | **보인다.** 밖에서 고칠 수 있다 |
| `private` (아무것도 안 쓰면 이것) | 안 보인다 |

⚠️ `public` 이어도 **변수가 메서드 밖, `class` 안**에 있어야 노출된다.

### Time.deltaTime  ★
**처음**: cp-07

**직전 프레임에서 지금 프레임까지 걸린 시간(초).**

| 1초에 그리는 장수 | `deltaTime` |
|---|---|
| 60장 | 약 0.017초 |
| 30장 | 약 0.033초 |
| 10장 | 약 0.1초 |

**빠른 PC 는 작고 느린 PC 는 크다.**

"1초에 갈 거리" 에 이걸 곱하면 **프레임이 짧으면 조금, 길면 많이** 움직여서
1초 뒤 위치가 어느 PC 에서나 같아진다.

> **비유** — "한 걸음에 5cm" 로 정하면 걸음 빠른 사람이 더 간다.
> "1초에 3m" 로 정하면 누구나 1초 뒤 같은 자리다.

⚠️ **움직임을 다루는 곳마다 곱한다.** cp-10(파이프 이동), cp-12(시간 재기)에서 다시 나온다.

### Orthographic Size
**처음**: cp-02

화면에 세로로 몇 칸이 보일지. **위아래 절반의 칸 수**를 적는다.

⚠️ 값이 **작을수록 확대**된다. 물건이 커진 게 아니라 카메라가 당겨진 것이다.

### 매 프레임 / 프레임 (Frame)
**처음**: cp-04

게임 화면은 아주 빠르게 그려지는 그림 여러 장이고, 그 한 장이 프레임이다.
보통 1초에 **60장쯤** 그린다. PC 성능에 따라 다르다.

> **비유** — 만화영화. 1초에 수십 장을 넘겨서 움직이는 것처럼 보이게 한다

`Update()` 는 **한 프레임에 정확히 한 번** 실행된다. (실측: 6842프레임 → 로그 6842줄)

### 대입 `=`  ★
**처음**: cp-05

**"오른쪽 값을 왼쪽 상자에 넣어라" 는 명령.** 수학의 "같다" 가 **아니다.**
방향이 있고, **오른쪽 → 왼쪽**이다.

**증거** — `score = score + 1` 은 수학이면 `0 = 1` 이 되어 말이 안 된다.
"오른쪽을 계산해서 왼쪽에 넣어라" 로 읽으면 완벽히 말이 된다.

⚠️ 이걸 "같다" 로 읽는 습관이 남아 있으면 cp-06 의 `+=` 부터 하나도 이해되지 않는다.

### 계속 일어나는 일 vs 한 번 일어나는 일  ★
**처음**: cp-08

`Time.deltaTime` 을 곱할지 말지를 가르는 기준.

| | 예 | `deltaTime` |
|---|---|---|
| **계속** 일어나는 일 | 낙하, 파이프 이동 | **곱한다** |
| **한 번** 일어나는 일 | 점프, 점수 +1 | **안 곱한다** |

⚠️ cp-07 직후라 모든 곳에 곱하고 싶어진다. 점프에 곱하면 0.017 배가 되어 거의 안 움직인다.

### 논리 연산자 `&&` / `||`  ★
**처음**: cp-09

조건 두 개를 묶는 방법.

| 기호 | 읽는 법 | 언제 참 |
|---|---|---|
| `&&` | **그리고** (AND) | **둘 다** 참일 때만 |
| `\|\|` | **또는** (OR) | **둘 중 하나라도** 참이면 |

⚠️ **최대 함정** — "천장에 닿았다 또는 바닥에 닿았다" 에 `&&` 를 쓰면
"천장에 닿았고 **그리고** 바닥에 닿았고" 가 되어 **영원히 거짓**이다. 절대 안 죽는다.
**컴파일 에러가 안 난다.**

### 단위 (프레임당 vs 초당)
**처음**: cp-07

같은 변수인데 뜻이 달라질 수 있다.

| | `fallSpeed` 의 뜻 | 값 |
|---|---|---|
| cp-06 | **한 프레임에** 갈 칸 수 | 0.05 |
| cp-07 | **1초에** 갈 칸 수 | 3 |

`0.05 × 60 = 3`. 값이 60배 커진 게 아니라 **단위가 바뀐 것**이다.

### 비교 연산자
**처음**: cp-09

| 기호 | 뜻 |
|---|---|
| `>` `<` | 크다 / 작다 |
| `>=` `<=` | 크거나 같다 / 작거나 같다 |
| `==` | **같은가?** |
| `!=` | 다른가? |

⚠️ **`=` 와 `==` 는 완전히 다르다.** `y = 3` 은 "넣어라", `y == 3` 은 "같은가?".
`if` 안에서는 언제나 `==` 다.

### 방향과 부호
**처음**: cp-06

y 는 값이 커지면 **위**로 간다. 그러니 **아래로 가려면 빼야 한다(`-`)**.

```
위로  →  y 를 크게  →  +
아래로 →  y 를 작게  →  -
```

변수 앞의 `-` 는 "이 값의 반대". `fallSpeed` 가 0.05 면 `-fallSpeed` 는 -0.05.

⚠️ 부호를 반대로 써도 **에러가 안 난다.** 컴파일은 되고 방향만 반대다. 화면을 보면 안다.

### 명암비
**처음**: cp-03 (더 알고 싶으면)

두 색의 **밝기** 차이. 1.0 이면 같고, 클수록 잘 구분된다. **3.0 이상이면 흑백으로 봐도 구분된다.**

색상(무슨 색인가)이 달라도 명암비가 낮으면 흑백 인쇄나 색약 상태에서 묻힌다.

### 변수 (Variable)
**처음**: cp-05

값을 담아두고 이름을 붙여둔 상자.

> **비유** — 이름표가 붙은 서랍

숫자를 그대로 쓰지 않고 상자에 담는 이유는 **이름이 있으면 무슨 뜻인지 알 수 있기 때문**이다.

### 상태 (state)
**처음**: cp-09

"지금 어떤 상황인가" 를 기억해두고, **그에 따라 다르게 동작하는 것.**

cp-09 에서는 `bool isDead` 하나로 "살았다/죽었다" 를 관리한다.

⚠️ `bool` 하나로는 상태를 **둘**밖에 표현 못 한다. 상태가 셋(대기/플레이/죽음)이 되는
cp-23 에서 `enum` 으로 바꾼다.

⚠️ **`public` 은 "사람이 조절할 값" 에만 붙인다.** `isDead` 는 코드가 알아서 관리하는
값이라 붙이지 않는다.

### 세미콜론 `;` / 중괄호 `{ }`
**처음**: cp-04

`;` 은 **한 문장의 끝**. 문장마다 반드시 붙인다.
`{ }` 는 **한 덩어리의 시작과 끝**. 반드시 짝이 맞아야 한다.

⚠️ 초보가 가장 많이 내는 에러가 이 둘이다. 빨간 줄이 뜨면 먼저 여기를 의심하자.

### 셰이더 (Shader)
**처음**: cp-03

물건을 화면에 **어떤 방식으로 그릴지** 정해둔 계산 규칙. 머티리얼 안에 하나 들어 있다.

> **비유** — 페인트의 종류. 유광이냐 무광이냐

이 프로젝트는 `Universal Render Pipeline/Lit` 을 쓴다. `Lit` = "빛을 받는다".
새 머티리얼을 만들면 자동으로 선택되므로 건드릴 일이 없다.

### 숫자 뒤의 `f`
**처음**: cp-05

"이건 `float` 이다" 라는 표시. `float newY = -1f;`

⚠️ **안 붙이면 `CS0664` 에러.** C# 은 `-1.0` 을 기본적으로 `double` 로 보기 때문에,
`float` 상자에 넣으려면 `f` 로 알려줘야 한다.

**규칙: 숫자를 `float` 에 넣을 땐 뒤에 `f` 를 붙인다.**

### 스크립트 (Script)
**처음**: cp-04

컴퓨터에게 시킬 일을 적어둔 파일. 확장자는 `.cs`.

> **비유** — 배우에게 주는 대본

⚠️ **만들기만 해서는 아무 일도 안 일어난다. 게임오브젝트에 붙여야 실행된다.**
스크립트도 컴포넌트다.

⚠️ **클래스 이름과 파일 이름이 반드시 같아야 한다.** 다르면 붙지 않는다.

### 자료형 (Type)
**처음**: cp-05

상자에 **무엇을 담을지** 미리 정하는 것.

| 자료형 | 담는 것 | 처음 |
|---|---|---|
| `float` | 소수점 있는 숫자 | cp-05 |
| `bool` | **참(`true`) 아니면 거짓(`false`)**, 둘 중 하나 | cp-09 |
| `int` | 정수 | cp-20 |

`bool` 은 스위치와 같다. 켜짐 아니면 꺼짐, 중간은 없다.
비교 연산자와 `Input.GetKeyDown` 이 내놓는 것도 `bool` 이라 `if` 조건에 바로 들어간다.

게임에서 위치·속도는 거의 다 소수라 **`float` 을 가장 많이 쓴다.**

### 컴파일 (Compile)

⚠️ **컴파일이 실패하면(Console 에 빨간 `CS` 줄) Play 버튼이 안 먹는다.** 빨간 줄부터 없앤다.

### Start() / Update()
**처음**: cp-04

**Unity 가 정해진 때에 대신 불러주는 두 개의 약속.**

| | 언제 | 몇 번 |
|---|---|---|
| `Start()` | Play 직후 | **딱 1번** |
| `Update()` | 매 프레임 | 1초에 수십 번 |

⚠️ **내가 부르는 게 아니다. Unity 가 알아서 불러준다.**

처음 한 번만 할 일 → `Start()` / 계속 반복할 일 → `Update()`

### transform.position
