Chapter 12

파이프를 설계도로 만들어
복제한다

11번에서 만든 파이프는 하나뿐이고, 지나가 버리면 끝이다. 게임이 되려면 계속 나와야 한다. 그렇다고 손으로 100개를 만들 수는 없다. 하나를 “설계도”로 만들어 두고, 코드로 찍어낸다.

읽는 시간 약 25분 · 실습 2 · 문항 2
학습 목표
  • 1씬의 오브젝트를 프리팹으로 저장할 수 있다.
  • 2프리팹(설계도)과 씬 인스턴스(실물)의 차이를 말할 수 있다.
  • 3Instantiate() 로 코드에서 오브젝트를 만들 수 있다.
  • 4public GameObject 칸에 Inspector 로 참조를 연결할 수 있다.
그림 12-1 · 씬에 없던 파이프가 Play 하면 생긴다
Hierarchy 를 보면 PipePair(Clone) 이라는 이름으로 나타난다. Stop 하면 사라진다.
12.1

손으로 100개를 만들 수는 없다

파이프를 계속 나오게 하려면 방법이 두 가지다.

방법문제
손으로 100개 만들어 늘어놓기만드는 데만 한나절. 색 하나 바꾸려면 100번 고쳐야 한다. 게임이 길어지면 부족해진다
하나를 설계도로 두고 코드로 찍어내기없다. 이게 정답이다

Unity 에서 이 “설계도”를 프리팹(Prefab) 이라고 한다.

이미 겪어봤다 03번에서 머티리얼 하나를 새와 바닥에 다 적용했을 때, 통 색을 바꾸니 둘 다 바뀌었다. 프리팹도 같은 성질이다. 하나를 고치면 그것으로 만든 것이 전부 바뀐다.
12.2

설계도와 실물

둘은 있는 곳부터 다르다.

프리팹씬 인스턴스기억할 것
어디에Project 창 (파일)Hierarchy (무대 위)창고 vs 무대
화면에안 보인다보인다설계도는 안 보인다
개수하나몇 개든설계도 하나로 여러 개
고치면이후 만들어지는 것이 전부 바뀐다그 하나만 바뀐다이게 핵심
비유 — 프리팹은 붕어빵 틀이고, 씬 인스턴스는 구워 나온 붕어빵이다. 틀을 고치면 이후 구워지는 붕어빵이 전부 바뀌지만, 이미 구운 붕어빵을 하나 고쳐도 틀은 그대로다.

(Clone) 이 붙는 이유

코드로 만든 오브젝트는 이름 뒤에 (Clone) 이 붙는다. PipePair 프리팹으로 만들면 PipePair(Clone) 이 된다. “이건 설계도가 아니라 찍어낸 것” 이라는 표시다.

Play 중에 만든 것은 저장되지 않는다 05번에서 배운 것이 여기서 또 나온다. Unity 는 Play 를 누른 순간의 씬을 기억했다가 Stop 할 때 되돌린다. Play 중에 생긴 (Clone) 은 Stop 하면 전부 사라진다. 이게 정상이다.
12.3

참조 — 칸에 끌어다 넣기

코드가 “어떤 프리팹을 찍어낼지” 알아야 한다. 그런데 코드에 파일 이름을 적어 넣는 방식은 쓰지 않는다. 이름을 바꾸는 순간 깨지기 때문이다.

대신 public GameObject 로 빈 칸을 만들어 두고, Inspector 에서 프리팹을 끌어다 넣는다. 이렇게 연결해 두는 것을 참조라고 한다.

PipeSpawner.csAssets/Scripts
public GameObject pipePrefab;   // Inspector 에 "Pipe Prefab" 칸이 생긴다

07번에서 public float 이 숫자 칸을 만들었던 것과 같다. public GameObject 는 오브젝트를 넣는 칸을 만든다.

연결이 안 되면 어떻게 되나
지금은 비어 있음
Inspector — Pipe Spawner (Script)
Pipe PrefabNone (Game Object)
Console
Play 하면 여기에 결과가 나온다

연결을 잊으면 NullReferenceException 이 난다. 10번에서 Rigidbody 를 안 붙였을 때와 같은 에러다 — “있어야 할 게 없다”는 뜻이다.

12.4

만들어 보자

1 · 프리팹으로 저장하기

순서할 일
1Project 창 Assets 에 Prefabs 폴더를 만든다 (오른쪽 클릭 → Create → Folder)
2Hierarchy 의 PipePair 를 Project 창의 Prefabs 폴더로 끌어다 놓는다
3Hierarchy 의 PipePair 이름이 파란색으로 바뀐다 — 프리팹과 연결됐다는 표시다

2 · 씬의 원본 지우기

Hierarchy 의 PipePair 를 삭제한다. 설계도는 Project 창에 남아 있으니 사라지지 않는다.

겁내지 말자 공들여 만든 걸 지우는 게 아깝게 느껴지지만, 설계도가 남아 있으면 언제든 다시 만들 수 있다. 이게 프리팹의 요점이다.

3 · 스포너 만들기

Hierarchy 빈 곳 오른쪽 클릭 → Create Empty → 이름을 PipeSpawner 로. 11번에서 PipePair 를 만들 때와 같은 방식이다. 눈에 보이는 것은 없고 일만 한다.

{
    public GameObject pipePrefab;

5 · 참조 연결하기 — 잊기 쉬운 단계

순서할 일
1PipeSpawner 스크립트를 PipeSpawner 오브젝트에 붙인다
2Inspector 에 Pipe Prefab 칸이 생긴 것을 확인한다
3Project 창의 PipePair 프리팹을 그 칸으로 끌어다 놓는다
정답 확인 스스로 채워 본 뒤에 펼치자
PipeSpawner.csAssets/Scripts
using UnityEngine;

public class PipeSpawner : MonoBehaviour
{
    public GameObject pipePrefab;

    void Start()
    {
        Instantiate(pipePrefab, new Vector3(11f, 0f, 0f), Quaternion.identity);
    }
}
조각뜻
Instantiate(A, B, C)A 설계도로 B 위치에 C 회전으로 하나 만들어라
Start()지금은 한 번만 만든다. 13번에서 여기를 Update() 로 옮겨 계속 나오게 한다

마지막 항목은 이렇게 확인한다

순서할 일
1Project 창의 PipePair 프리팹을 더블클릭 — 프리팹 편집 화면이 열린다
2PipeTop 의 Position y 를 4 → 5 로 (틈이 넓어진다)
3왼쪽 위 < 화살표로 씬으로 돌아온 뒤 Play
4새로 생긴 파이프의 틈이 넓어졌는지 본다. 확인이 끝나면 4 로 되돌린다
이 교재를 만들면서 실제로 해봤다 — PipeTop 의 y 를 4 → 5 로 고치자 새로 생긴 클론의 틈이 3.00칸 → 4.00칸 으로 바뀌었다. 씬에는 파이프가 하나도 없는데도 바뀐 값으로 나온다.

문항 1 · Stop 하면 왜 사라지나

Play 중에 생긴 PipePair(Clone) 이 Stop 하면 사라지는 이유는?

A코드가 Stop 할 때 지우기 때문
BUnity 가 Play 전 씬 상태로 되돌리기 때문
C프리팹으로 만든 것은 원래 저장되지 않기 때문
05번에서 배운 것과 같다. Unity 는 Play 를 누른 순간의 씬을 기억했다가 Stop 할 때 그대로 되돌린다. Play 중에 생긴 것은 그 기억에 없으므로 사라진다. Inspector 값을 Play 중에 바꿔도 사라지는 것과 같은 이유다.

문항 2 · 이미 나온 파이프는

파이프 3개가 화면에 흘러가는 중에 프리팹의 색을 빨강으로 바꿨다. 화면의 3개는?

A전부 빨강이 된다
B아무것도 안 바뀌고, 새로 생기는 것도 그대로다
C경우에 따라 다르다 — 무엇을 바꿨느냐에 달렸다
색은 머티리얼에 있다. 03번에서 배웠듯 머티리얼은 따로 있는 파일이고, 파이프들이 그것을 함께 쓴다. 그래서 머티리얼 색을 바꾸면 이미 나온 것까지 전부 바뀐다.

반면 프리팹의 구조(위치·크기·컴포넌트)를 바꾸면 이후에 만들어지는 것부터 적용된다. 붕어빵 틀을 고쳐도 이미 구운 붕어빵은 안 바뀌는 것과 같다.
12.6

막혔을 때

증상원인과 해결
NullReferenceException가장 흔하다. Pipe Prefab 칸이 비어 있다. Project 창의 프리팹을 끌어다 넣자. 10번의 Rigidbody 를 안 붙였을 때와 같은 에러다
파이프가 두 개 생긴다씬의 PipePair 를 안 지웠다. 원본이 남아 있고 클론이 또 생긴 것이다
Inspector 에 Pipe Prefab 칸이 없다public 을 안 붙였거나 변수가 메서드 안에 있다. 07번을 다시 보자
칸에 프리팹이 안 들어간다Hierarchy 의 오브젝트가 아니라 Project 창의 프리팹을 끌어야 한다
프리팹을 고쳤는데 안 바뀐다Play 중에 고쳤다면 Stop 할 때 되돌아간다. Stop 상태에서 고치자
Stop 했더니 파이프가 없다정상이다. Play 중에 생긴 것은 저장되지 않는다

13번 예고

지금은 Start() 에서 한 번만 만든다. 계속 나오게 하려면 Update() 로 옮겨야 하는데, 그냥 옮기면 매 프레임 하나씩 = 1초에 60개가 쏟아진다. 13번에서 “몇 초마다 한 번”을 만드는 법을 배운다. 07번의 Time.deltaTime 이 이번엔 곱하는 게 아니라 더하는 데 쓰인다.
