> **이번 목표** — 새가 천장이나 바닥에 닿으면 **죽는다.** 죽으면 모든 조작이 멈춘다.

| 바닥에 닿아 죽음 | 천장에 닿아 죽음 |
|---|---|
| ![](../shots/cp-09/floor.png) | ![](../shots/cp-09/ceiling.png) |

**2부의 마지막이다.** 여기까지 하면 "새를 조종하는 것" 이 완성된다. 다음 부에서는 장애물을 만든다.

---

## 시작하기 전에

- [ ] 스페이스를 누르면 새가 위로 튄다
- [ ] 연타하면 화면 안에 떠 있을 수 있다
- [ ] 지금은 **바닥을 뚫고 지나가** 화면 밖으로 사라진다 ← 이걸 고친다

## 알아야 할 것

### 비교 연산자

**두 값을 비교해서 참/거짓을 내놓는다.**

| 기호 | 뜻 | 예 (`y` 가 3 일 때) |
|---|---|---|
| `>` | 크다 | `y > 5` → 거짓 |
| `<` | 작다 | `y < 5` → 참 |
| `>=` | **크거나 같다** | `y >= 3` → 참 |
| `<=` | **작거나 같다** | `y <= 3` → 참 |
| `==` | 같다 | `y == 3` → 참 |
| `!=` | 다르다 | `y != 3` → 거짓 |

⚠️ **`=` 와 `==` 는 완전히 다르다.**

| | 뜻 |
|---|---|
| `y = 3` | **넣어라** (05번에서 배운 대입) |
| `y == 3` | **같은가?** (참/거짓을 내놓음) |

**`if` 안에서는 언제나 `==` 다.** 실수로 `=` 를 쓰면 에러가 난다.

### `bool` — 참 아니면 거짓

**참(`true`) 또는 거짓(`false`), 둘 중 하나만 담는 상자**다.

```csharp
bool isDead = false;    // 처음엔 살아있다
isDead = true;          // 죽었다
```

> **비유** — 스위치. 켜짐 아니면 꺼짐, 중간은 없다.

비교 연산자가 내놓는 것도 `bool` 이다. `Input.GetKeyDown(...)` 이 내놓는 것도 `bool` 이다. **그래서 `if` 의 조건 자리에 들어갈 수 있다.**

### `!` — 반대로 뒤집기

**참이면 거짓으로, 거짓이면 참으로** 뒤집는다.

```csharp
bool isDead = false;

if (isDead)     // 거짓 → 안 들어감
if (!isDead)    // 참   → 들어감  ("죽지 않았다면")
```

> **읽는 법** — `!isDead` 는 **"isDead 가 아니라면"**, 즉 **"안 죽었다면"** 이다.

### `&&` 와 `||` ★

**조건 두 개를 묶는 방법**이다. 이번 항목에서 가장 헷갈리는 부분이다.

| 기호 | 읽는 법 | 언제 참인가 |
|---|---|---|
| `&&` | **그리고** (AND) | **둘 다** 참일 때만 |
| `\|\|` | **또는** (OR) | **둘 중 하나라도** 참이면 |

`\|` 는 백슬래시 옆에 있는 세로 막대다. **두 개를 붙여 쓴다.**

**우리가 만들 조건**

> "천장에 닿았다 **또는** 바닥에 닿았다" → 죽는다

```csharp
if (transform.position.y >= 4.5f || transform.position.y <= -3.5f)
```

⚠️ **여기서 `&&` 를 쓰면 절대 죽지 않는다.**

`&&` 는 "천장에 닿았다 **그리고** 바닥에 닿았다" 가 된다.
새가 동시에 천장에도 바닥에도 있을 수는 없으니, **이 조건은 영원히 거짓**이다.

**컴파일 에러가 안 난다.** 문법은 맞기 때문이다. 그냥 아무 일도 안 일어난다.

### 상태에 따라 다르게 동작하기

지금까지 코드는 **언제나 똑같이** 동작했다. 이제 **"죽었나 살았나" 에 따라 달라져야** 한다.

- 살아있으면 → 내려가고, 점프하고, 죽었는지 확인한다
- 죽었으면 → **아무것도 안 한다**

이걸 `bool` 하나로 관리한다. 이게 **상태(state)** 라는 개념의 시작이다.

```csharp
if (!isDead)
{
    ... 살아있을 때만 하는 일 전부 ...
}
```

⚠️ **`isDead` 에는 `public` 을 안 붙인다.** 이건 코드가 알아서 관리하는 값이지, 사람이 Inspector 에서 만질 값이 아니다. **`public` 은 "사람이 조절할 값" 에만 붙인다.**

## 해보기

### 1. 순서부터 세운다

이번에 할 일은 이것이다.

> **새가 천장(y = 4.5)이나 바닥(y = −3.5)에 닿으면 죽는다. 죽으면 아무 조작도 안 먹는다.**

한국어로 적어보자. **세 줄이면 된다.**

```
1. ________________________________
2. ________________________________
3. ________________________________
```

> 막히면 이 셋을 답해보자.
> - "죽었다" 를 코드가 기억하려면 무엇이 필요한가?
> - 죽었는지 어떻게 판단하나? 조건이 **몇 개**이고 **어떻게** 묶어야 하나?
> - 죽은 뒤에 낙하와 점프를 멈추려면 그 코드들을 어디에 넣어야 하나?

**왜 4.5 와 −3.5 인가** — 02번에서 계산한 값이다.

```
바닥 윗면 = -4.0  →  새(높이 1)가 얹히면 중심은 -4.0 + 0.5 = -3.5
화면 위끝 =  5.0  →  새 윗면이 화면 끝에 닿으면 중심은  5.0 - 0.5 =  4.5
```

### 2. 코드 고치기

```csharp
using UnityEngine;

public class BirdMove : MonoBehaviour
{
    public float fallSpeed = 3f;
    public float jumpPower = 1.5f;

    ________ isDead = ________;

    void Update()
    {
        if (________)
        {
            transform.position += new Vector3(0f, -fallSpeed * Time.deltaTime, 0f);

            if (Input.GetKeyDown(KeyCode.Space))
            {
                transform.position += new Vector3(0f, jumpPower, 0f);
            }

            if (transform.position.y > 4.5f)
            {
                transform.position = new Vector3(-3f, 4.5f, 0f);
            }

            if (transform.position.y ____ 4.5f ____ transform.position.y ____ -3.5f)
            {
                isDead = ________;
                Debug.Log("Dead");
            }
        }
    }
}
```

**빈칸 힌트**

| 빈칸 | 힌트 |
|---|---|
| `isDead` 앞 | 참/거짓만 담는 자료형 |
| `isDead` 값 | 게임을 시작할 때 새는 살아있다 |
| 바깥 `if` 조건 | **"안 죽었다면"**. 뒤집는 기호를 쓴다 |
| 마지막 `if` 의 세 칸 | 천장은 **위쪽**, 바닥은 **아래쪽**. 두 조건을 **또는**으로 묶는다 |
| `isDead =` 뒤 | 죽었다 |

> **가운데 `if (transform.position.y > 4.5f)` 는 이미 채워져 있다.**
> 왜 필요한지는 아래 「더 알고 싶으면」에서 설명한다. 지금은 그냥 두자.

### 3. 저장하고 Play

`Ctrl + S` → Unity → **Play**

- 아무것도 안 누르면 → 새가 바닥에 **얹혀서 멈춘다**
- 그 뒤 스페이스를 눌러도 → **아무 반응 없다**
- Console 에 **`Dead`** 가 **한 줄** 찍혀 있다

## 확인하기

**Console 의 `Collapse` 를 끈 상태로 확인하자.**

- [ ] 아무것도 안 누르면 새가 **바닥 위에 얹혀서** 멈춘다 (파고들지 않는다)
- [ ] 스페이스를 마구 눌러 위로 올라가면 **천장에서 멈춘다**
- [ ] 죽은 뒤 스페이스를 **아무리 눌러도 반응이 없다**
- [ ] Console 의 `Dead` 로그가 **딱 한 번만** 찍힌다

### `Dead` 가 계속 찍히면

죽은 뒤에도 판정이 계속 돌고 있다는 뜻이다. **죽음 판정이 `if (!isDead)` 바깥에 있는지** 확인하자.

---

## 안 되면

### 새가 바닥을 뚫고 계속 내려간다

**원인 1** — 조건에 `&&` 를 썼다.

```csharp
if (y >= 4.5f && y <= -3.5f)    // 영원히 거짓 → 절대 안 죽는다
if (y >= 4.5f || y <= -3.5f)    // 정상
```

새가 동시에 천장에도 바닥에도 있을 수는 없다. **`&&` 로는 절대 참이 되지 않는다.**
**컴파일 에러가 안 나서** 화면을 봐야 안다.

**원인 2** — 부등호 방향이 반대다.

```csharp
y >= -3.5f    // 틀림 — 바닥보다 "위" 라는 뜻이라 시작하자마자 죽는다
y <= -3.5f    // 정상 — 바닥보다 "아래"
```

### 시작하자마자 바로 죽는다

**원인** — 부등호 방향이 반대다. 위의 원인 2 를 보자.

새는 y = 0 에서 시작한다. `y >= -3.5` 는 `0 >= -3.5` 라서 **처음부터 참**이다.

### `Dead` 가 수천 줄 찍힌다

**원인 1** — 죽음 판정이 `if (!isDead)` **바깥**에 있다. 죽은 뒤에도 매 프레임 판정이 돌아서 계속 찍힌다.

**원인 2** — `isDead = true;` 를 안 썼다. 죽었다고 기억을 안 하니 매 프레임 다시 죽는다.

**원인 3** — Console 의 `Collapse` 가 켜져 있어서 1줄로 보이는데, 사실은 수천 줄일 수도 있다. **Collapse 를 끄고** 다시 보자. (04번)

### 죽었는데도 스페이스를 누르면 튄다

**원인** — 점프 코드가 `if (!isDead)` **바깥**에 있다.

낙하·점프·죽음판정 **셋 다** 바깥 `if` 안에 들어가야 한다.

### `CS0029` 에러가 난다

```
CS0029: 'int' 형식을 'bool' 형식으로 암시적으로 변환할 수 없습니다
```

**원인** — `bool` 상자에 참/거짓이 아닌 걸 넣었다. `0` 이나 `1` 은 안 된다. `true` / `false` 만 된다.

### `if` 안에서 `=` 를 썼다

```csharp
if (isDead = true)    // 틀림 — "넣어라" 라서 항상 참이 된다
if (isDead == true)   // 맞음
if (isDead)           // 더 간단하고 같은 뜻
```

## 그래도 안 되면 — 답

> 「순서부터 세운다」를 스스로 해봤다면 봐도 된다.

**순서 예시**

1. "죽었나?" 를 기억할 상자를 만든다 (처음엔 거짓)
2. **안 죽었을 때만** 내려가고, 점프하고, 죽음을 판정한다
3. 천장 **또는** 바닥에 닿았으면 죽었다고 표시하고 로그를 한 번 찍는다

**완성 코드** — `Assets/Scripts/BirdMove.cs`

```csharp

public class BirdMove : MonoBehaviour
{
    public float fallSpeed = 3f;
    public float jumpPower = 1.5f;

    bool isDead = false;

    {

}
```

## 더 알고 싶으면

### 가운데 `if` 는 왜 있나 — 점프가 천장을 훌쩍 넘는 문제

```csharp
if (transform.position.y > 4.5f)
{
    transform.position = new Vector3(-3f, 4.5f, 0f);
}
```

이 줄이 없으면 이런 일이 생긴다. 실제로 재본 값이다.

```
천장선(4.5) 바로 아래인 4.4999 에서 스페이스를 누르면
→ 점프는 즉시 1.5칸이므로 y = 5.9999 로 뛴다
→ 새 아랫면이 5.4999. 화면 위끝은 5.0
→ 새가 완전히 화면 밖으로 나가서 안 보이는 채로 죽는다
```

이 줄을 넣으면 넘어간 만큼을 **천장선으로 되돌려 놓는다.**

```
보정 후 y = 4.5000 → 새 윗면 5.0000 = 화면 위끝. 딱 붙어서 보인다
```

**왜 바닥은 보정 안 하나?**

낙하와 점프는 **넘어가는 양이 다르기 때문**이다.

| | 한 번에 움직이는 양 | 넘어가는 양 (실측) |
|---|---|---|
| 낙하 | 프레임당 약 0.05칸 | **0.0124칸** |
| 점프 | 한 번에 **1.5칸** | 최대 **1.5칸** |

바닥은 0.0124칸(화면에서 약 1픽셀) 밖에 안 넘어가서 **눈에 안 보인다.** 천장은 최대 1.5칸이라 새가 통째로 사라진다.

**조금씩 움직이는 것과 한 번에 뛰는 것의 차이**다. 08번의 `deltaTime` 이야기와 같은 뿌리다.

> **18번에서는 이 줄이 필요 없어진다.** 물리를 쓰면 점프도 조금씩 올라가기 때문이다.

### `bool` 하나로 상태를 관리하는 것의 한계

지금은 상태가 **둘뿐**이다 — 살았다 / 죽었다. `bool` 하나로 충분하다.

나중에 상태가 **셋**이 되면 어떻게 될까?

```
시작을 기다리는 중 / 플레이 중 / 죽음
```

`bool` 하나로는 두 가지밖에 표현 못 한다. **23번에서 이 문제를 만난다.** 지금은 몰라도 된다.

### 죽었는데 화면이 안 멈춘다

지금은 **새만** 멈춘다. 파이프가 생기면 파이프는 계속 흘러갈 것이다.

**화면 전체를 멈추는 건 17번에서 한다.** 지금은 새 하나만 있으니 티가 안 난다.

3. 죽음 판정을 && 로 넣어 Play → 여전히 뚫린다 → 조건을 소리내어 읽힌다
4. || 로 고쳐 Play → 얹힌다
5. 천장 보정 줄을 지우고 마구 연타 → 새가 위로 사라진다 → 다시 넣는다

## 분량
- 내가 걸린 시간: 코드 10분 + 검증 40분 (천장 오버슈트 발견·수정 포함)
- 학생 예상: 50~70분. 조건이 처음이라 오래 걸린다
- 수업 배분 의견: **&& / || 를 칠판에서 충분히 다룬다.** 코드로 가기 전에
  "비 오고 그리고 우산 있으면" / "비 오거나 또는 눈 오면" 같은 일상 예로 감을 잡게 한다
