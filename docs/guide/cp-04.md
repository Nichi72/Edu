> **이번 목표** — 새에 첫 코드를 붙이고, `Start` 와 `Update` 가 **언제 몇 번 실행되는지**를 눈으로 확인한다.

화면은 하나도 안 변한다. **바뀌는 건 Console 창이다.**

이 항목은 이 수업 전체에서 가장 중요한 항목 중 하나다. **`Start` 와 `Update` 의 차이를 모르면 05번부터 전부 막힌다.**

---

## 시작하기 전에

- [ ] Game 뷰에 노란 새와 초록 바닥이 보인다
- [ ] `Assets` 아래에 `Scripts` 폴더가 있다

---

## 알아야 할 것

### 스크립트 (Script)

**컴퓨터에게 시킬 일을 적어둔 파일**이다. 우리는 C# 이라는 언어로 적는다.

> **비유** — 배우에게 주는 대본. 언제 무슨 말을 하고 어떻게 움직일지 적혀 있다.

파일 확장자는 `.cs` 다.

### 스크립트를 "붙인다"

스크립트는 **만들기만 해서는 아무 일도 안 일어난다.** 게임오브젝트에 **붙여야** 실행된다.

기억하자 — 스크립트도 **컴포넌트**다. Transform 이나 Mesh Renderer 처럼, 게임오브젝트에 붙는 능력 하나다.

> **비유** — 대본을 써놓기만 하면 아무 일도 안 생긴다. **배우에게 쥐여줘야** 연기가 시작된다.

⚠️ **가장 흔한 실수** — 코드를 다 쓰고 "왜 안 되지?" 하는데, 붙이는 걸 잊은 경우다.

### 클래스 (class) 와 파일 이름

코드를 열면 이런 줄이 있다.

```csharp
public class BirdMove : MonoBehaviour
```

- `BirdMove` 가 **클래스 이름**이다
- `: MonoBehaviour` 는 "이건 게임오브젝트에 붙일 수 있는 부품이다" 라는 뜻이다

⚠️ **아주 중요** — **클래스 이름과 파일 이름이 반드시 같아야 한다.**
`BirdMove.cs` 파일 안의 클래스는 `BirdMove` 여야 한다. 다르면 붙지 않는다.

### 프레임 (Frame)

게임 화면은 **아주 빠르게 그려지는 그림 여러 장**이다. 그 한 장이 프레임이다.

> **비유** — 만화영화. 1초에 수십 장을 넘겨서 움직이는 것처럼 보이게 한다.

보통 1초에 **60장 정도** 그린다. PC 성능에 따라 다르다.

### `Start()` 와 `Update()`

**Unity 가 정해진 때에 대신 불러주는 두 개의 약속**이다.

| | 언제 실행되나 | 몇 번 |
|---|---|---|
| `Start()` | Play 를 누른 직후, **딱 한 번** | 1번 |
| `Update()` | **매 프레임마다** | 1초에 수십 번 |

⚠️ **가장 헷갈리는 것** — **내가 부르는 게 아니다. Unity 가 알아서 불러준다.**
우리는 "이런 이름으로 적어두면 Unity 가 그때 실행해준다" 는 약속을 따를 뿐이다.

이 약속을 이용해서 이렇게 나눠 쓴다.

- 처음 한 번만 할 일 → `Start()`
- 계속 반복할 일 → `Update()`

### `Debug.Log()`

**Console 창에 글자를 찍는 명령**이다.

> **비유** — 코드 안에 심어두는 확인 도장. "여기까지는 왔다" 를 남긴다.

게임 화면에는 안 보이고 **개발자만 본다.** 코드가 실제로 실행됐는지 확인할 때 쓴다.
**앞으로 뭔가 안 될 때마다 이걸 쓰게 된다.**

### Console 창

**`Debug.Log` 로 찍은 글자와 에러 메시지가 나오는 창**이다.

> 안 보이면: `Window > General > Console`

Console 창 위쪽에 버튼이 몇 개 있는데, 그중 **`Collapse`** 를 꼭 알아야 한다.

| `Collapse` | 하는 일 |
|---|---|
| **켜짐** | **똑같은 메시지를 한 줄로 합쳐서** 보여준다 (옆에 몇 번인지 숫자) |
| **꺼짐** | 나온 순서대로 **전부 따로** 보여준다 |

⚠️ **이번 항목에서는 반드시 `Collapse` 를 꺼야 한다.** 켜져 있으면 6000번 실행된 것도 **1줄로 보여서** 한 번만 실행된 줄 알게 된다. 이번 항목의 확인이 통째로 망가진다.

### 컴파일 (Compile)

**사람이 쓴 코드를 컴퓨터가 실행할 수 있는 형태로 바꾸는 일**이다.

Unity 는 `.cs` 파일을 저장하면 **자동으로** 컴파일한다. 에디터 오른쪽 아래에 동그란 표시가 잠깐 도는 게 그것이다.

- 컴파일이 **성공**하면 아무 일도 없다
- **실패**하면 Console 에 빨간 줄이 뜬다 (`CS` 로 시작하는 에러)

⚠️ **컴파일이 실패하면 Play 버튼을 눌러도 안 된다.** 빨간 줄부터 없애야 한다.

### 세미콜론 `;` 과 중괄호 `{ }`

| | 뜻 |
|---|---|
| `;` | **한 문장의 끝.** 문장마다 반드시 붙인다 |
| `{ }` | **한 덩어리의 시작과 끝.** 반드시 짝이 맞아야 한다 |

⚠️ **초보가 가장 많이 내는 에러가 이 둘이다.** 빨간 줄이 뜨면 먼저 여기를 의심하자.

## 해보기

### 1. 순서부터 세운다

이번에 할 일은 이것이다.

> **Play 를 누르면, 시작할 때 한 번 글자를 찍고, 그 뒤로는 계속 글자를 찍는다.**

컴퓨터한테 시킨다고 생각하고 한국어로 적어보자. **두 줄이면 된다.**

```
1. ________________________________
2. ________________________________
```

> 막히면: 위 「알아야 할 것」의 `Start()` / `Update()` 표를 다시 보자. **"딱 한 번" 과 "매 프레임" 중 어느 쪽이 어디에 들어갈까?**

**이게 왜 중요한가** — 앞으로 모든 항목에서 이 질문을 먼저 한다. *"이건 한 번만 할 일인가, 계속 할 일인가?"* 코드를 어디에 쓸지가 여기서 정해진다.

### 2. 스크립트 만들기

1. **Project** 창에서 `Assets` > `Scripts` 폴더를 클릭한다
2. 폴더 안 **빈 곳에서 오른쪽 클릭** → `Create` > `Scripting` > `MonoBehaviour Script`
3. 이름이 파랗게 선택된 상태에서 **`BirdMove`** 를 입력하고 `Enter`

> Unity 버전에 따라 `Create > C# Script` 로 있는 경우도 있다. 같은 것이다.
> **이름을 나중에 바꾸면 클래스 이름과 어긋나서 안 붙는다.** 만들 때 바로 정하자.

### 3. 코드 쓰기

만든 `BirdMove` 를 **더블클릭**하면 코드 편집기가 열린다.

안에 이미 뭔가 적혀 있다. **전부 지우고** 아래를 그대로 친다. **복사하지 말고 직접 치자.**

```csharp
using UnityEngine;

public class BirdMove : MonoBehaviour
{
    void Start()
    {
        Debug.Log("_____________");
    }

    void Update()
    {
        Debug.Log("_____________");
    }
}
```

빈칸에는 **화면에서 구분할 수 있는 아무 글자**나 넣으면 된다. 이 교재는 이렇게 넣었다.

- `Start` 안에는 → `"Start 실행됨"`
- `Update` 안에는 → `"Update 실행됨"`

> 큰따옴표 `"` 를 빼먹지 말자. 글자는 반드시 따옴표 안에 넣어야 한다.

다 쓰면 **`Ctrl + S` 로 저장**하고 Unity 로 돌아온다. 오른쪽 아래 동그라미가 한 바퀴 돌면 컴파일이 끝난 것이다.

### 4. 새에 붙이기

1. **Hierarchy** 에서 `Bird` 를 클릭한다
2. **Project** 창의 `BirdMove` 를 마우스로 집어서
3. **Inspector 의 아래쪽 빈 곳**에 떨어뜨린다

> Inspector 맨 아래 `Add Component` 버튼을 눌러 `BirdMove` 를 검색해도 된다.

**확인** — `Bird` 의 Inspector 맨 아래에 `Bird Move (Script)` 라는 칸이 생겼으면 성공이다.

### 5. Console 준비하기

1. `Window > General > Console` 로 Console 창을 연다
2. 창 위쪽의 **`Collapse` 버튼이 눌려 있지 않은지** 확인한다. 눌려 있으면 **꺼둔다**
3. `Clear` 를 눌러 창을 비운다

### 6. Play

가운데 위의 **▶ (Play)** 버튼을 누른다. **3초쯤 두고 다시 눌러 끈다.**

## 확인하기

Console 창을 보자.

- [ ] `Start 실행됨` 이 **딱 1줄**만 있다
- [ ] `Update 실행됨` 이 **아주 많이** 쌓여 있다
- [ ] `Collapse` 는 꺼져 있다

### 말로 설명해보기 ★

> **`Start` 는 1줄인데 `Update` 는 왜 계속 쌓일까? 자기 말로 설명해보자.**

이걸 설명할 수 있으면 통과다. **못 하면 다음으로 넘어가지 말자.** 05번부터는 이걸 안다고 치고 진행한다.

> 힌트가 필요하면 — 「알아야 할 것」의 `Start()` / `Update()` 표를 다시 읽어보자.

## 안 되면

### `Update 실행됨` 이 1줄만 보인다

**원인** — `Collapse` 가 켜져 있다.

`Collapse` 는 **똑같은 메시지를 한 줄로 합친다.** 실제로는 수천 번 실행됐는데 1줄로 보인다.

이 교재를 만들면서 실제로 재본 값이다.

| | Console 에 보이는 줄 수 |
|---|---|
| `Collapse` **켬** | `Update 실행됨` **1줄** (실제로는 6842번 실행됨) |
| `Collapse` **끔** | `Update 실행됨` **6842줄** |

같은 상황인데 1줄과 6842줄로 보인다. **Collapse 를 끄자.**

### 아무 로그도 안 나온다

**원인 1** — 스크립트를 `Bird` 에 **안 붙였다.**
`Bird` 의 Inspector 맨 아래에 `Bird Move (Script)` 가 있는지 확인하자.

**원인 2** — Play 를 안 눌렀다. 코드는 Play 중에만 실행된다.

### 빨간 줄이 뜨고 Play 가 안 된다

Console 의 빨간 줄 **첫 줄**을 읽어보자. `CS` 로 시작하는 번호가 있다.

| 자주 나오는 에러 | 뜻 | 볼 곳 |
|---|---|---|
| `CS1002` | `;` 을 빼먹었다 | 에러가 난 줄의 **끝** |
| `CS1513` | `}` 이 모자란다 | 중괄호 짝이 맞는지 |
| `CS0103` | 모르는 이름이 있다 | 철자·대소문자 |
| `CS0116` | 코드가 클래스 밖에 있다 | 중괄호 위치 |

⚠️ **대소문자를 구분한다.** `debug.log` 는 안 되고 `Debug.Log` 여야 한다.

### 스크립트가 안 붙는다 (드래그해도 안 들어감)

**원인** — **파일 이름과 클래스 이름이 다르다.**

`BirdMove.cs` 파일이면 안에 `public class BirdMove` 여야 한다. 파일을 만든 뒤에 이름을 바꿨다면 코드 안의 클래스 이름은 안 바뀐다.

**고치는 법** — 코드를 열어 `public class 여기` 를 파일 이름과 똑같이 고친다.

### Console 창이 안 보인다

`Window > General > Console`

## 그래도 안 되면 — 답

> 「순서부터 세운다」를 스스로 해봤다면 봐도 된다.

**순서 예시**

1. 시작할 때 한 번 글자를 찍는다 → `Start()` 안에
2. 매 프레임마다 글자를 찍는다 → `Update()` 안에

**완성 코드** — `Assets/Scripts/BirdMove.cs`

```csharp
using UnityEngine;

public class BirdMove : MonoBehaviour
{
    void Start()
    {
        Debug.Log("Start 실행됨");
    }

    void Update()
    {
        Debug.Log("Update 실행됨");
    }
}
```

**각 줄이 하는 일**

| 줄 | 하는 일 |
|---|---|
| `using UnityEngine;` | Unity 기능을 쓰겠다는 선언. 없으면 `Debug` 를 못 찾는다 |
| `public class BirdMove : MonoBehaviour` | 게임오브젝트에 붙일 수 있는 부품 하나를 만든다 |
| `void Start()` | Play 직후 **한 번** 실행될 덩어리 |
| `void Update()` | **매 프레임** 실행될 덩어리 |
| `Debug.Log("...")` | Console 에 글자를 찍는다 |

---

## 더 알고 싶으면

### `Update` 는 정확히 몇 번 실행되나

이 교재를 만들면서 실제로 세어봤다.

```
Play 한 시간 동안 그려진 프레임 수 : 6842
Console 에 쌓인 Update 로그 줄 수  : 6842      ← 정확히 같다
Console 에 쌓인 Start 로그 줄 수   : 1
```

**`Update` 는 한 프레임에 정확히 한 번씩 실행된다.** 많이도 적게도 아니다.

이 사실이 **07번에서 아주 중요해진다.** "매 프레임 실행된다" 는 말은 곧 **"PC 가 빠르면 더 많이 실행된다"** 는 뜻이기 때문이다. 지금은 그런 게 있다는 것만 기억해두자.

### `void` 는 뭔가

`void Start()` 의 `void` 는 **"돌려주는 값이 없다"** 는 뜻이다.

지금은 몰라도 된다. **17번에서** 값을 돌려주는 것을 만들면서 다시 만난다.

## 먼저 겪게 할 것
- **Collapse 를 켠 채로 먼저 Play 시킨다.** Update 가 1줄로 보이는 걸 겪게 한 뒤에
  Collapse 를 끄게 한다. "같은 상황인데 화면이 다르게 보인다" 는 경험이
  앞으로 Console 을 믿고 읽는 태도를 만든다. 먼저 알려주면 이 경험이 사라진다
- **스크립트를 만들고 붙이지 않은 채 Play** 시켜본다. "만든 것 ≠ 실행되는 것" 을
  몸으로 알게 한다. 이건 12번 프리팹, 21번 참조 연결에서 계속 반복되는 감각이다

## 시연 절차
1. 스크립트를 만들고 **붙이지 않은 채** Play → 아무 일도 안 일어남을 보여준다
2. 붙이고 다시 Play → 로그가 쏟아진다
3. Collapse 를 켰다 껐다 하며 같은 로그가 1줄 ↔ 수천 줄로 보이는 걸 보여준다
4. Console 의 줄 수와 "1초에 몇 프레임" 을 연결해준다

## 설명 게이트 ★
syllabus 체크가 "그 차이를 자기 말로 설명한다" 로 끝난다. **반드시 확인하고 넘어간다.**
- 통과 기준: "Start 는 처음에 한 번, Update 는 계속" 을 자기 말로 하면 된다
- 부실한 답: "그냥 그렇게 되는 거", "Update 니까 업데이트되는 것" → 한 번 되묻는다
- 두 번 부실하면 질문을 멈추고 **Console 줄 수를 직접 세게 한다.** 시험이 아니라 실습이다

## 검증 기록
| 체크 문장의 조건 | 결과 | 근거 |
|---|---|---|
| Collapse 끈 상태에서 Start 로그 1줄 | O | LogEntries 로 직접 계수: Start 1줄 |
| Collapse 끈 상태에서 Update 로그 계속 쌓임 | O | Update 6842줄 |
| 그 차이를 설명 (설명 게이트) | O | Update 줄 수 == Time.frameCount == 6842. 매 프레임 정확히 1회임이 수치로 확인됨 |

검증 방법: Roslyn 으로 UnityEditor.LogEntries 리플렉션 —
LogEntries.Clear() → EditorApplication.isPlaying=true → SetConsoleFlag(1, on/off) 로
Collapse 를 토글하며 GetEntryInternal 로 메시지별 계수. GetEntryCount 로 접힌 실제 발생 횟수도 확인.

실측값:
- Collapse 켬: Update 1줄 (실제 발생 6842회)
- Collapse 끔: Update 6842줄
- Time.frameCount = 6842 → Update 는 프레임당 정확히 1회
- Start 는 어느 쪽이든 1줄
