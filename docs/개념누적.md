## 특히 조심할 4가지 함정

이 넷은 놓치기 쉽고, 놓치면 그 항목 교재가 통째로 못 쓰게 된다.

### ① 17번 전에는 **메서드를 만들 수 없다**

`void 메서드로 묶기` 가 **17**에서야 열린다. `return` 이 있는 메서드는 **16**.
→ **04~15의 모든 코드는 `Start()` 와 `Update()` 안에 인라인으로 들어간다.** 아무리 길어져도 쪼개지 않는다.
→ 그 "길어져서 답답한 상태"를 겪는 것이 17번의 학습 동기다. 미리 정리해주면 17번이 죽는다.

### ② 24번 전에는 **매개변수 있는 메서드를 못 쓴다**

17에서 열리는 건 `void 메서드`뿐이고, syllabus 24 개념에 `매개변수가 있는 메서드`가 따로 적혀 있다.
→ **17~23의 메서드는 전부 매개변수 없는 `void Xxx()` 형태다.**

### ③ 07번 전에는 **`public` / `private` 를 쓸 수 없다**

05~06에서 필드는 선언하되 **접근제한자를 안 붙인다.** (C# 기본값이 private이라 동작에는 문제없다)
```csharp
float fallSpeed = 0.05f;   // 05~06은 이렇게
public float fallSpeed;    // 07부터 이렇게
```

### ④ 13번 전에는 **`Destroy()` 가 없다 — 파이프가 무한히 쌓인다**

10~12는 파이프가 화면 밖으로 나가도 계속 남는다. **이건 버그가 아니라 의도된 설계다.**
cp-13 체크 문장이 그 깨달음("`Destroy` 없으면 느려진다")을 통과 기준으로 삼고 있다.
→ 10~12 구현 시 "정리 코드가 없네" 하고 미리 넣으면 안 된다.

### 2부 — 새를 띄운다

#### cp-02 화면과 좌표를 확정한다
- **새로 열림**: 씬 / 게임오브젝트 / 컴포넌트 / Transform(위치·회전·크기) / Orthographic 카메라 / Game 뷰 화면 비율 / 씬 저장
- **코드**: 없음 (에디터 조작만)
- 못 씀: 스크립트 전부

#### cp-03 색을 입힌다 [아트·기획]
- **새로 열림**: 머티리얼 만들기 / 셰이더가 무엇인지 한 줄 / 드래그해서 적용
- **코드**: 없음

#### cp-04 새에 첫 코드를 붙인다
- **새로 열림**: 스크립트 만들기 / 오브젝트에 붙이기 / `Start()` / `Update()` / `Debug.Log()` / Console 창 읽는 법
- 못 씀: 변수, `if`, 그 외 전부. **`Debug.Log()` 호출 두 줄이 코드의 전부다.**

#### cp-05 새가 딱 한 칸 아래로 내려간다
- **새로 열림**: 변수와 자료형(`float`) / `new Vector3(...)` / `transform.position` 에 통째로 대입(`=`)
- 위치는 `Start()` 안. `Update()` 아님 (그건 06)
- 못 씀: `+=`, `public`, `Time.deltaTime`, `if`

#### cp-06 새가 계속 내려간다
- **새로 열림**: `Update()` 로 옮기기 / `+=` / 방향과 부호
- **못 씀: `Time.deltaTime`** ← 07에서 열린다. 프레임당 고정값으로 내린다
- 못 씀: `public`, `if`

#### cp-07 숫자를 코드 밖에서 만지고, 어느 PC에서나 같게 만든다
- **새로 열림**: `public` / `private` / Inspector 노출 / 프레임의 의미 / `Time.deltaTime`
- `Application.targetFrameRate` 를 검증에 사용 (체크 문장에 명시)
- 못 씀: `if`

#### cp-08 스페이스를 누르면 위로 튄다
- **새로 열림**: `if` / `Input.GetKeyDown(KeyCode.Space)` / 누른 순간 vs 누르는 동안
- **못 씀: `else`** — syllabus 개념에 `if` 만 있다. 09의 `bool`/`!` 이 열리기 전까지 단일 `if` 로 간다
- 못 씀: `Rigidbody` (18), 비교 연산자 (09)

#### cp-09 천장이나 바닥에 닿으면 죽는다
- **새로 열림**: 비교 연산자(`<` `>` `<=` `>=`) / `||` `&&` / `bool` / `!` / 상태에 따라 다르게 동작
- 바닥 판정은 **y 좌표 비교로 한다.** `Collider` 는 19에서 열린다
- 못 씀: `OnCollisionEnter`, 태그

### 3부 — 장애물을 만든다

#### cp-10 파이프 한 쌍이 흘러온다
- **새로 열림**: 빈 게임오브젝트(Create Empty) / 부모-자식 구조 / 자식 Inspector 위치는 로컬
- 이동 코드는 **06~07의 것을 축만 바꿔 재사용** (y → x, 부호 반대)
- **못 씀: `Instantiate` (11), `Destroy` (13)** — 씬에 손으로 놓은 파이프 하나가 지나가고 끝이다

#### cp-11 파이프를 설계도로 만들어 복제한다
- **새로 열림**: 프리팹 / 프리팹 vs 씬 인스턴스 / `Instantiate()` / Inspector 참조 연결(`public GameObject`)
- 스폰은 `Start()` 에서 1회. **반복 스폰은 12**
- 못 씀: `Destroy`, 시간 누적

#### cp-12 파이프가 몇 초마다 계속 나온다
- **새로 열림**: 시간 재기(변수 누적 + `if` + 리셋) / `Time.deltaTime` 재사용
- **못 씀: 코루틴, `InvokeRepeating`** ← 목차에 아예 없다. `timer += Time.deltaTime` 패턴만
- 못 씀: `Destroy` → 파이프가 계속 쌓이는 게 정상

#### cp-13 지나간 파이프를 치운다
- **새로 열림**: `Destroy()` / 위치 조건 판정 / `gameObject` 와 `this` 의 차이 / Pause·Step 버튼

#### cp-14 파이프 높이가 매번 달라진다
- **새로 열림**: `Random.Range` 와 범위 / 클래스와 인스턴스(같은 스크립트라도 각자 값을 가진다)
- 못 씀: 배열 (16)

#### cp-15 시작하자마자 파이프가 깔려 있다
- **새로 열림**: `for` 반복문 / 시작값·증가폭·반복 횟수 / 숫자를 박지 않고 계산해서 쓰기 / `GetComponent<PipeMove>().speed` **(맛보기 — 18에서 본격)**
- 체크 문장이 "`Spawn Interval` 이나 `Speed` 를 바꿔도 간격이 유지될 것"을 요구 → **간격을 상수로 박으면 실패한다**

#### cp-16 파이프 높이를 우리가 짠 순서대로 내보낸다 [아트·기획]
- **새로 열림**: 배열 / 인덱스 / `.Length` / **값을 돌려주는 메서드(`return`)** / `List` 는 한 줄 설명만
- **`.Length` 를 반드시 쓴다** — 배열 크기를 바꿔도 다른 곳을 안 고치는 게 체크 기준
- 못 씀: `List` 실사용, LINQ

### 4부 — 죽음과 물리

#### cp-17 죽으면 화면 전체가 멈춘다
- **새로 열림**: 중앙 관리 오브젝트(`GameManager`) / `FindFirstObjectByType<T>()` / **`void` 메서드로 묶기** / 여러 스크립트가 한 값을 함께 보기 / 같은 처리가 두 번 돌지 않게 막기

- 손으로 짠 낙하 코드를 **걷어낸다**

#### cp-19 파이프에 부딪히면 죽는다
- **새로 열림**: `Collider` / 충돌 이벤트에 한쪽 `Rigidbody` 필요 / `OnCollisionEnter` / 태그 만들기+지정(두 단계) / `CompareTag` / `isKinematic`

## 좌표 기준값 (syllabus 체크 문장에서 확정된 것)

임의로 바꾸면 체크 문장이 깨진다.

| 값 | 출처 |
|---|---|
| 바닥 윗면 `y = -4` (바닥 오브젝트 `y = -4.5`, 스케일 1) | cp-02 |
| 새 시작 위치: 화면 왼쪽 가운데 | cp-02 |
| Aspect `16:9`, 배경 하늘색 | cp-02 |
| 낙하: Play 후 **3초 안에** 화면 아래로 사라짐 | cp-06 |
| 천장 `y = 4.5` / 바닥 `y = -3.5` 에서 죽음 | cp-09 |
| 파이프 출발 `x = 11`, **7~8초** 뒤 화면 밖 | cp-10 |
| 스폰 간격 `2` 초, 파이프 속도 `3` | cp-12, cp-15 |
| 화면 안 파이프 `5개 이하` 유지 | cp-13 |
| 미리 깔아둘 파이프 `2개` | cp-15 |

→ 파이프 속도 3, x=11 출발이면 화면 왼쪽 밖(약 x=-11)까지 22칸 / 3 ≒ **7.3초**. cp-10의 "7~8초"와 맞는다.
→ 간격 2초 × 속도 3 = 파이프 사이 거리 **6**. cp-12의 "간격 × 속도 = 거리" 와 맞는다.
