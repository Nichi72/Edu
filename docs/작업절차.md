# 작업 절차

이 프로젝트는 여러 세션에 걸친다. **대화 기억이 끊겨도 이 파일만 읽으면 이어갈 수 있어야 한다.**

---

## 목적

`syllabus.md` 의 커리큘럼(00~30)을 **실제로 만들어보면서 검증하고**, 그 과정에서 나온 것을 교재 재료로 쌓는다.

- 교재를 상상으로 쓰면 틀린다. 초보가 어디서 막히는지는 **직접 만들어봐야만** 나온다
- **`syllabus.md` 는 검증 대상이다.** 논리에 안 맞으면 고친다 — 단, 아래 "수정 기준"을 통과해야 한다
- **교재는 항목을 만들자마자 그 자리에서 쓴다.** 몰아서 쓰면 "어디서 막혔는지"가 기억에서 사라진다

### 독자 — 이게 모든 판단의 기준이다

**Unity 도 프로그래밍도 아예 모르는 학생이, 혼자 읽고 진도를 뺄 수 있어야 한다.**

- "Hierarchy 에서 우클릭" 을 모른다고 전제한다. **메뉴 경로는 전부 적는다**
- **처음 나오는 용어는 반드시 먼저 설명한다.** 설명 없이 쓰지 않는다.
  `docs/guide/용어사전.md` 에 없는 말을 본문에서 그냥 쓰면 그건 실패다
- 문장은 짧게. 한 문단 3줄을 넘기지 않는다
- **"이건 당연히 알겠지" 가 이 교재에서 가장 위험한 생각이다**

### 답을 싣는다 — 단, 맨 뒤에

`CLAUDE_Test_.md` 의 튜터 규칙은 "완성 코드를 통째로 주지 마라" 다. 그런데 학생이 혼자
진도를 빼려면 답이 있어야 한다. **정면으로 부딪힌다.**

답을 없애는 대신 **순서로 푼다** — 순서 세우기 → 빈칸 코드 → 확인하기 → 안 되면 →
**그래도 안 되면 답**. 스스로 해본 뒤에 답을 보게 되고, 혼자서도 막히지 않는다.

- 답 절 앞에 **"여기까지 스스로 해봤다면 봐도 된다"** 를 반드시 붙인다
- 튜터(Claude)는 여전히 답을 주지 않는다. 교재의 답은 학생이 **자기 판단으로** 여는 것이다

## 항목 하나당 루프 — 이 7단계를 그대로 반복한다

### 1. 개념 확인
`docs/개념누적.md` 에서 **이 항목까지 열린 문법**을 확인한다.
뒤 항목의 개념은 더 좋은 방법이라도 쓰지 않는다. 학생이 그 시점에 쓸 수 있는 코드여야 교재가 된다.

> 특히 조심: 17 전엔 메서드 없음 / 24 전엔 매개변수 없는 메서드만 / 07 전엔 `public` 없음 / 13 전엔 `Destroy` 없음

### 2. 구현
| 대상 | 도구 |
|---|---|
| 코드 | `script-update-or-create` |
| 씬 오브젝트 | `gameobject-create` / `gameobject-modify` / `gameobject-component-add` / `gameobject-component-modify` |
| 머티리얼·프리팹 | `assets-material-create` / `assets-prefab-create` |
| 컴파일 확인 | `console-get-logs` → `CS` 에러 0건 |

### 3. 검증
syllabus `체크 cp-XX` 문장을 **조건 단위로 쪼개서** 각각 O/X 와 근거를 남긴다.

- **`script-execute` 는 `Debug.Log` 말고 문자열을 반환시킨다.** 로그는 스택트레이스가 20줄씩 붙어 낭비가 크다
- 입력이 필요한 항목(08·22·23)은 Roslyn 으로 오토파일럿을 **메모리에만** 컴파일해 붙였다 뗀다 → 디스크에 안 써지므로 커밋에 안 섞인다
- `Input.GetKeyDown` **바인딩 자체**는 원리상 자동화 불가 → 그 셋만 사람이 키를 눌러 확인

### 4. syllabus 와 어긋나면 → 수정 (아래 "수정 기준" 참조)

### 5. 교재 챕터 집필 — **미루지 않는다**
`docs/guide/cp-XX.md` 작성. 서식은 `docs/guide/_템플릿.md`.

**이건 "원재료 메모"가 아니라 완성된 교재 챕터다.** 그 항목을 막 만든 직후, 기억이 남아 있을 때 쓴다.
23개를 다 만든 뒤에 cp-04 에서 뭐가 헷갈렸는지 복원하려 하면 결국 상상으로 쓰게 되고,
그러면 직접 만들어보는 이 방식의 의미가 통째로 사라진다.

- **"안 되면" 절은 진짜 겪은 것만 적는다.** 없었으면 "없음"이라고 적는다
- **이번에 처음 나오는 용어를 전부 「알아야 할 것」에 넣고, `용어사전.md` 에도 추가한다.**
  둘 중 하나라도 빠지면 그 챕터는 미완성이다
- 챕터 머리말 주석에 **상태 / 근거커밋 / 의존값**을 남긴다 (아래 "챕터 관리" 참조)
- 챕터 맨 끝 주석 블록에 **교수용 정보**(먼저 겪게 할 것 / 시연 절차 / 분량 / 검증 기록)를 남긴다
  → Phase 3 에서 이것만 뽑아 `guide.md`(교수용 지도서)로 만든다. 파일을 둘로 나누면 어긋난다

### 6. 씬 저장
`scene-save`. 빼먹으면 커밋에 안 들어간다.

### 7. 커밋 + 태그
```
<부> cp-XX - <syllabus 제목 그대로>
```
태그 `cp-XX`. **모든 커밋은 각각 Play 되는 상태여야 한다** — `git checkout cp-12` 로 그 시점이 재현돼야 한다.

부 번호: 2부 02~09 / 3부 10~16 / 4부 17~19 / 5부 20~24 / 6부 25~26

## syllabus 수정 기준

**계산만으로는 고치지 않는다.** 아래를 전부 통과해야 손댄다.

| # | 조건 |
|---|---|
| 1 | **실측했다** — 실제로 Play 해서 값을 쟀다. 종이 계산은 "의심"이지 "근거"가 아니다 |
| 2 | **2회 이상 재현했다** — 한 번은 우연일 수 있다 |
| 3 | **대안을 재봤다** — 지금 값이 왜 안 되고 새 값이 왜 되는지 둘 다 측정했다 |
| 4 | **의도가 아니다** — 어긋나 보이는 게 사실은 학습 장치인지 확인했다. `docs/이슈.md #5`(cp-06 의 "3초")가 그런 예다. **이건 고치면 안 된다** |

**절대 바꾸지 않는 것**
- **항목 번호와 `cp-XX` 식별자.** `CLAUDE_Test_.md` 의 설명 게이트가 cp-02·03·05·09·18·26 을 지목하고 있어서, 번호가 밀리면 튜터 규칙이 깨진다
- **`체크` 문장이 요구하는 "학생이 도달해야 할 결론".** 숫자·조건은 고쳐도, 깨달음을 앞당겨 알려주는 방향으로는 못 고친다

**고칠 때**
1. `docs/이슈.md` 에 실측값과 판단 근거를 남긴다
2. `syllabus.md` 를 고친다
3. 커밋 메시지에 **무엇을 왜 고쳤는지 + 실측 근거**를 적는다
4. 나중에 `guide.md` 를 쓸 때 같은 내용이 반영돼야 한다 (syllabus 주석: 항목 번호·제목·체크 문장은 guide 와 항상 같아야 한다)

## 챕터 관리 — 앞 챕터가 뒤 항목 때문에 틀려지는 것을 막는다

챕터를 그때그때 쓰면 기억이 살아 있다는 큰 이점이 있지만, **대가가 하나 있다.**
뒤 항목에서 값이 바뀌면 이미 써둔 앞 챕터가 조용히 틀려진다.

실제로 이런 일이 예정돼 있다:

| 언제 | 무엇이 바뀌나 | 틀려지는 챕터 |
|---|---|---|
| cp-15 | `Spawn Interval`·`Speed` 를 바꿔가며 검증한다 | cp-10, cp-12 의 소요 시간·간격 |
| cp-18 | 손으로 짠 낙하를 물리로 갈아엎는다 | cp-05~09 의 "완성 코드"가 최종본이 아님 |
| cp-23 | `bool` 상태를 `enum` 으로 바꾼다 | cp-17, cp-22 의 코드 |
| 언제든 | syllabus 수정이 발생 | 그 값을 인용한 모든 챕터 |

**그래서 챕터마다 머리말 주석에 셋을 남긴다.**

```
상태:     초안 | 확정 | 재검토필요
근거커밋: <이 챕터를 쓴 시점의 커밋 해시>
의존값:   <이 챕터가 기대는 숫자들. 예: 파이프 속도 3, Ortho Size 5>
```

**규칙**
1. 항목을 끝내고 챕터를 쓰면 **`초안`** 으로 시작한다
2. 어떤 항목에서 값을 바꾸면, **그 값을 `의존값` 에 적어둔 챕터를 전부 `재검토필요` 로 바꾼다.**
   이때 고치지는 않는다 — 표시만 한다. 진도를 멈추지 않기 위해서다
3. Phase 2 에서 `재검토필요` 를 전부 훑어 고치고 **`확정`** 으로 올린다
4. `확정` 이 아닌 챕터가 하나라도 있으면 Phase 3(조립)로 넘어가지 않는다

**의존값에 반드시 적어야 하는 것**: 좌표·속도·시간·간격처럼 **뒤에서 바뀔 수 있는 숫자**.
"화면 왼쪽 끝 x=−8.89" 같은 실측값도 포함한다. 코드 자체가 뒤에서 갈아엎히는 경우(cp-18, cp-23)도
의존값 대신 `뒤에서 대체됨: cp-18` 처럼 적는다.
