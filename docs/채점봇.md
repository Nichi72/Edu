# 채점 봇 — 수업 끝 통과 처리와 과제 수집

학생은 Unity 「제출」 버튼이 만든 zip 을 디스코드 봇 DM 에 올린다.
봇은 선생님의 그 시점 프로젝트와 **포함 비교**해 통과/미통과를 답하고, 구글 시트에 한 줄 남긴다.
교탁컴·집컴 어디서 켜도 같다. **디스코드 서버 하나가 수업 하나**다 — 수업이 여럿이면 서버를 하나씩 두고 봇을 초대만 한다.

```
학생 Unity ─제출 버튼─▶ zip ─DM─▶ 봇 (python, 켜진 컴) ─▶ 학생에게 답장
                                   │                      └▶ #채점실 한 줄 · 구글 시트 한 행
선생님 Unity ─같은 버튼─▶ zip ─/진도 7일차─▶ 봇 (기준으로 저장, 과녁으로)
```

| 것 | 위치 | 역할 |
|---|---|---|
| 제출 버튼 | `Assets/Editor/Submit/SubmitTool.cs` | Unity 메뉴 「제출」. 스크립트·씬·프리팹·머티리얼·설정 일부를 zip 으로. 학생·선생님 공용 |
| 봇 | `bot/` | 디스코드 봇 + 채점 엔진. `run.bat` 으로 켠다 |
| 채점 엔진 | `bot/grader/` | 디스코드 없이도 `python -m grader.cli` 로 돌려볼 수 있다 |
| 기록 | 구글 시트 「제출」「명단」「상태」 + `bot/data/` | 시트가 거울, 로컬이 캐시. 학번과 이름은 따로 열에 둔다 |

## 한 번만 하는 준비

### 1. 디스코드 봇 만들기 (10분)

1. https://discord.com/developers/applications → **New Application** → 이름(예: 채점봇)
2. 왼쪽 **Bot** → **Reset Token** → 토큰 복사 (한 번만 보인다) → `.env` 의 `DISCORD_TOKEN`
3. 같은 화면 아래 **Privileged Gateway Intents** → **MESSAGE CONTENT INTENT** 켜기 → Save
4. 왼쪽 **OAuth2** → **URL Generator** → Scopes: `bot`, `applications.commands`
   → Bot Permissions: `View Channels`, `Send Messages`, `Read Message History`, `Attach Files`, **`Manage Channels`**
   → 아래 URL 을 열어 수업 서버에 초대. **이 URL 을 저장해 둔다** — 수업(서버)이 늘 때마다 같은 URL 로 초대만 하면 된다
5. 봇이 들어가면 그 서버에 **#채점실** 비공개 채널을 스스로 만들고(관리자에게만 보인다) 명령을 등록한다.
   `Manage Channels` 를 안 줬으면 #채점실 채널을 직접 만들어 봇을 넣는다
6. (선택) 디스코드 설정 → 고급 → **개발자 모드** 켜기 → 내 프로필 우클릭 **ID 복사** → `TEACHER_IDS`.
   비워 두면 #채점실에 글을 쓸 수 있는 사람은 누구나 명령을 쓸 수 있다 (채널이 비공개라 보통 그걸로 충분)

### 2. 구글 시트 연결 (10분, 안 해도 봇은 돈다)

1. 새 구글 시트를 만든다. URL 의 `/d/` 와 `/edit` 사이 글자가 `SHEET_ID`
2. https://console.cloud.google.com → 프로젝트 하나 → **API 및 서비스 ▸ 라이브러리** → *Google Sheets API* 사용 설정
3. **사용자 인증 정보 ▸ 서비스 계정 만들기** → 만든 계정 클릭 → **키 ▸ 키 추가 ▸ JSON** → 내려받은 파일을
   `bot/` 안에 두고 경로를 `GOOGLE_SA_JSON` 에 (예: `service-account.json`)
4. 시트의 **공유** 에 그 서비스 계정 이메일(`…@….iam.gserviceaccount.com`)을 **편집자**로 추가

시트 탭은 봇이 처음 켜질 때 알아서 만든다.

### 3. 봇 설치 (컴마다)

1. 파이썬 3.11 이상 설치 (python.org, **Add to PATH** 켜기)
2. `bot/` 폴더를 그 컴에 둔다 (이 저장소를 clone 했으면 그대로)
3. `bot/.env.example` 을 복사해 `bot/.env` 로 만들고 토큰을 채운다. 서버 ID 는 안 적는다. **`INSTANCE` 는 컴마다 다르게** (교탁컴 / 집컴)
4. `bot/run.bat` 더블클릭. 처음엔 가상환경을 만드느라 1분쯤 걸린다
5. 창에 `준비 끝 · 수업 N개: …` 이 뜨면 된 것. 디스코드에서 봇이 초록불

두 번째 컴에는 `bot/` 폴더(`.env` 포함)를 복사하고 `INSTANCE` 만 바꾼다. 기준·명단은 디스코드와 시트에서 복원되므로 `data/` 는 복사하지 않아도 된다.

### 4. 학생 프로젝트에 제출 버튼 넣기

`Assets/Editor/Submit/` 폴더를 학생 프로젝트의 `Assets/Editor/` 아래에 복사한다.
튜터 패키지로 배포한다면 `tools/build-tutor-package.py`(main 브랜치)의 ErrorCapture 줄 옆에
`write('Assets/Editor/Submit/SubmitTool.cs', read('Assets/Editor/Submit/SubmitTool.cs'))` 를 더하고
`install.bat` 에 복사 한 줄을 추가한다.

## 수업 날

1. 교탁컴에서 `run.bat`. (집컴이 켜져 있어 봇이 이미 돌고 있으면 "다른 컴에서 돌고 있다" 하고 꺼진다 — 그래도 된다)
2. 평소대로 수업
3. 수업 끝: 선생님 Unity 에서 **제출 ▸ 과제 zip 만들기** → #채점실에서 **`/진도 항목:7일차 기준:(그 zip)`**
   봇이 `[기준] 7일차 …` 메시지를 올리고 과녁을 7일차 로 잡는다
4. 학생에게 "제출" 이라고 말한다. 학생은 Unity 제출 버튼 → zip 을 봇 DM 에 드래그 → 몇 초 뒤 답장
5. **`/현황`** 으로 통과 / 미통과 / 미제출 명단을 본다. 미통과 학생은 고쳐서 다시 올리면 된다 (횟수 제한 없음)
6. 끝나면 창을 닫는다. 집에서 집컴 `run.bat` 을 켜 두면 밤에 올라온 제출도 바로 채점된다

**수업이 여럿이면** 서버를 수업마다 하나씩 두고 봇을 같은 초대 URL 로 초대한다. 기준·과녁·명단·현황은 서버마다 따로 돈다.
학생이 봇 DM 에 처음 zip 을 올리면 봇이 그 학생이 들어 있는 수업 서버를 찾아 그 수업으로 등록한다
(여러 수업 서버에 있으면 번호로 고르게 한다. 한 학생은 수업 하나에 속하고, 옮기려면 그 서버 #채점실에서 `/등록`).
시트는 하나고 「수업」 열(서버 이름)로 나뉜다.

**항목 이름은 자유다.** `7일차`, `1028`, `cp-07`, `과제1` 다 된다 (공백과 `/ \ : * ? " < > |` 만 빼고 30자 이하).
이름 속 **숫자**로 순서를 알고, 숫자를 뺀 나머지가 같으면 **같은 계열**로 본다 — `6일차 → 7일차 → 10일차` 는 한 줄이고 `과제1` 은 다른 줄이다.
그래서 매번 같은 이름꼴을 쓰는 게 좋다 (`N일차` 로 정했으면 계속 `N일차`).

**과제도 똑같다.** 과제 정답 상태를 선생님 프로젝트에서 만들어 `/진도 항목:과제1 기준:(zip)`. 학생 제출은 과제1 기준으로 본다. 다시 수업 진도로 돌아갈 땐 `/과녁 8일차` 또는 다음 `/진도`.

### 학생에게 보낼 안내 (복사용)

> **과제 제출 방법**
> 1. Unity 위 메뉴 **제출 ▸ 과제 zip 만들기** 를 누른다 (저장 안 한 씬은 저장된다)
> 2. 열린 폴더의 zip 파일을 디스코드 **채점봇** 에게 DM 으로 보낸다 (봇 프로필 클릭 → 메시지 보내기 → 파일 드래그)
> 3. 처음 한 번은 봇이 학번과 이름을 묻는다. `20241234 홍길동` 처럼 띄어서 한 줄로 보내면 바로 채점한다
> 4. 몇 초 뒤 결과가 온다. 미통과면 빠진 것을 고쳐서 다시 올린다. 몇 번이든 된다
> 봇이 회색(오프라인)이어도 올려 두면 된다. 켜질 때 채점한다.

### 선생님 명령 (#채점실에서만)

| 명령 | 뜻 |
|---|---|
| `/진도 항목 기준` | 기준 zip 저장 + 과녁 지정. 같은 항목에 다시 올리면 덮어쓴다 |
| `/과녁 항목` | 기준은 그대로, 과녁만 바꾼다 |
| `/현황 [항목]` | 통과 / 미통과(몇 회, 빠진 것) / 미제출 |
| `/명단` | 이 수업에 등록된 학생과 디스코드 계정 |
| `/다시채점 학생 [자세히]` | 그 학생의 마지막 제출을 지금 기준으로. `자세히` 면 빠진 문장까지 선생님에게만 |
| `/등록 학생 학번 이름` | 학번·이름 고치기, 이 수업으로 옮기기. 봇에게 DM 을 안 보낸 학생을 미리 등록하는 데도 쓴다 |
| `/도움` | 이 표 |

## 어떻게 판정하나

**기준에 있는 것이 학생에게 다 있으면 통과.** 학생이 더 가진 것은 안 본다.

| 보는 것 | 단위 | 안 보는 것 |
|---|---|---|
| 스크립트 | 파일 → 클래스(이름, 상속) → `using` → 변수(이름, 자료형, public 여부) → 메서드(이름) → **문장** | 주석, 공백, 줄 순서, 문자열 내용, **숫자 값**(속도 3 이든 5 든), `Debug.Log` |
| 씬 | 오브젝트(경로) → 켜짐 → 컴포넌트 종류 | Inspector 의 값 (아래 예외 빼고) |
| 프리팹·머티리얼 | 있는가, 프리팹 안의 오브젝트·컴포넌트 | |
| 값 예외 | 카메라 위치·Orthographic·Size, `activeInputHandler` | `bot/grader.yaml` 에서 바꾼다 |

문장은 `transform.position += new Vector3(0f, -fallSpeed, 0f);` 를 `transform.position+=new Vector3(N,-fallSpeed,N)` 으로 다듬어 비교한다.
그래서 **이름이 다르면 떨어진다** — 수업에서 약속한 대로다.

학생에게는 "Update() 안에 빠진 문장 1개", "변수 fallSpeed 가 없다" 까지만 보인다. 빠진 문장이 무엇인지는 `/다시채점 … 자세히` 로 선생님만 본다.

**도달 진도**: 같은 계열 기준이 5일차, 6일차, 7일차 쌓여 있으면 셋 다 대보고 **통과한 것 중 가장 높은 항목**을 도달로 본다.
(cp-07 상태의 코드는 cp-06 의 문장이 바뀌어 cp-06 기준에는 떨어진다. 그래서 "앞에 것 전부 통과" 로 보지 않는다.)

### 기준을 만들 때

- 수업 끝 상태 그대로 제출 버튼을 누르면 된다. **실험하다 남긴 코드·오브젝트가 있으면 학생도 그걸 가져야 통과**하니 지우고 누른다
- `Debug.Log` 는 기준에 있어도 학생에게 요구하지 않는다 (`grader.yaml` 의 `ignore_statements`)
- 기준을 잘못 올렸으면 같은 항목으로 `/진도` 를 다시 하면 덮어쓴다

## 알아둘 것

- **봇이 꺼져 있어도 제출은 안 사라진다.** 켜질 때 명단에 있는 학생들의 DM 을 거슬러 올라가(기본 14일) 못 본 zip 을 채점하고 그때 답장한다. 꺼진 사이 여러 번 올렸으면 전부 기록하되 답장은 마지막 것 하나. **한 번도 등록 안 한 학생**은 디스코드가 봇에게 DM 목록을 안 줘서 켜질 때는 못 찾고, 그 학생이 다음에 아무 글이나 보내는 순간 올려 둔 zip 을 찾아 이름을 묻고 채점한다
- 두 컴에서 동시에 켜면 뒤에 켠 쪽이 스스로 꺼진다 (시트 「상태」 의 심장박동, 2분). 시트를 안 쓰면 이 잠금이 없으니 한 번에 한 컴만 켠다
- 디스코드 첨부 한도는 10 MB. 제출 버튼은 2 MB 넘는 파일을 빼므로 보통 수백 KB 다. 학생이 프로젝트 폴더를 통째로 압축해 올려도 Library 는 버리고 받는다
- 제출 zip 안의 `submit-manifest.json` 에 Unity 버전·시각·**기기 해시**가 있다. 시트의 「기기」열이 같은데 이름이 다르면 같은 PC 에서 나온 제출이다
- 학생 제출 zip 은 `bot/data/submissions/` 에 남는다. `/다시채점` 은 그 컴에 zip 이 있어야 한다
- **아직 없는 것**: 자유 과제(각자 다른 설계)를 결과로 판정하는 Play 실행 검사, LLM 피드백, 유사도 검사. 봇과 규칙 파일에 자리만 비워 뒀다

## 문제가 생기면

| 증상 | 볼 곳 |
|---|---|
| 봇이 안 켜진다 / 바로 꺼진다 | 창의 마지막 줄. 토큰 오타, `MESSAGE CONTENT INTENT` 안 켬이 대부분 |
| 슬래시 명령이 안 보인다 | 초대 URL 에 `applications.commands` 가 있었는지. 디스코드를 Ctrl+R 로 새로고침. #채점실에서만 먹는다 |
| 창에 "#채점실 채널이 없고 만들 권한도 없다" | 그 서버에 #채점실 채널을 직접 만들어 봇을 넣거나, 초대 URL(`Manage Channels` 포함)로 다시 초대한다 |
| 학생 DM 에 "수업 서버에 들어와 있지 않다" | 그 학생이 #채점실이 있는 서버의 멤버가 아니다. 서버 초대 링크를 준다 |
| 학생 DM 에 반응이 없다 | 봇이 켜져 있는지(초록불). 학생이 서버 멤버인지(같은 서버에 있어야 DM 이 열린다) |
| 시트에 안 올라간다 | 서비스 계정 이메일을 시트에 **편집자**로 공유했는지. 봇은 못 보낸 행을 모아 뒀다가 복구되면 올린다 |
| "다른 컴에서 이미 봇이 돌고 있다" | 진짜 돌고 있으면 그대로 둔다. 저쪽이 죽은 거면 2분 뒤 다시 켠다 |
| 기준이 이상하다 | `bot/.venv/Scripts/python -m grader.cli --pair 기준.zip 제출.zip --teacher` 로 직접 본다 |
| 창에 "응답 시간(3초)을 놓쳤다" / Unknown interaction | 봇 창 안을 클릭하면 Windows 콘솔이 '선택 모드'가 되어 봇이 멈춘다 (이제 클릭으로는 안 멈추게 해 뒀다). 창에서 Esc 를 누르고 명령을 다시 한다. 로그를 보고 싶으면 `bot/data/bot.log` 를 연다 |

## 파일

```
Assets/Editor/Submit/SubmitTool.cs   제출 버튼 (학생 프로젝트에 복사)
bot/
  run.bat            켜기
  .env.example       설정 본보기 → .env
  main.py            디스코드 봇
  store.py           SQLite 캐시 + 구글 시트 + 심장박동
  refs.py            기준 보관
  grader.yaml        값 예외·무시 목록
  grader/            채점 엔진 (bundle 읽기 → csharp / unityyaml 구조 뽑기 → compare 포함 비교 → report)
  tests/             pytest. fixtures/ 는 cp-XX 태그에서 뽑은 조각
  data/              (git 밖) bot.db, guilds/<서버ID>/refs/, submissions/, bot.log
```
