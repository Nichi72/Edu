## 기획서를 쓴다

==플래피 버드를 해 보고, 게임에 무엇이 있고 각각 어떻게 움직이는지 글로 적는다.==

왜 코드보다 글이 먼저일까? AI 에게 만들어 달라고 하든 내가 직접 만들든, **무엇을 만들지 정확히 말할 수 있어야** 만들 수 있다.

> **명세** — ==만들 것을 다른 사람이 읽고 똑같이 만들 수 있게 적은 것.== AI 에게 시킬 때도 이 글이 그대로 명령이 된다. 내가 내부를 잘 알수록 명세가 정확해진다.

웹에서 플래피 버드를 직접 해 본다.

> 멈춤 — 화면에 보이는 것을 전부 말해 보자. 그리고 각각이 어떻게 움직이는지.

같이 정리하면 이렇다.

```text
플래피 버드
최소 플레이가 가능한 수준을 목표로

플레이어
기본적인 이동 로직
오른쪽으로 계속 나아감.
중력으로 인해서 계속 아래로 떨어짐
스페이스를 통해 점프
위 방향으로 스페이스를 눌렀을때 점프를 한다.

파이프
파이프는 오른쪽에서 일정한 간격으로 생성이됨.
생성된 파이프는 왼쪽으로 이동한다. // 아닐수있음.
사이에 있는 공간이 있는데 이 공간의 위치가 랜덤하게 바뀜.

게임오버 조건
파이프에 닿으면 게임 오버
땅에 닿으면 게임 오버

스코어
파이프의 사이를 지나면 점수가 1점씩 오른다.

UI
점수가 표현된다.
```

> **기획서** — 명세를 모은 문서. ==거창할 필요 없다. 게임 요소를 나누고, 각각 어떻게 움직이는지 한 줄씩 적으면 된다.==

두 군데를 짚고 넘어간다.

- **`// 아닐수있음`.** 화면에서는 파이프가 다가오는 것처럼 보인다. 그런데 새가 앞으로 가는 것일 수도 있다. ==보이는 것과 만드는 방법은 다를 수 있다.== 확실하지 않으면 표시해 두고 넘어간다. 우리는 새가 앞으로 가는 쪽으로 만든다.
- **뺀 것.** 죽으면 다시 시작하기, 새가 기울어지기. 목표가 「최소 플레이가 가능한 수준」 이라 이번엔 적지 않는다.

## 스크립트를 만든다

==Bird 를 움직일 스크립트 `BirdMove` 를 만들어 Bird 에 붙인다.==

1. Project 창에서 `Assets/Script` 클릭
2. 빈 곳에서 오른쪽 클릭 → **Create > Scripting > MonoBehaviour Script**
3. 이름이 파랗게 선택된 상태에서 `BirdMove` 입력 → Enter
4. `BirdMove` 를 Hierarchy 의 `Bird` 위에 끌어다 놓는다

==이름은 만들 때 정한다.== 나중에 바꾸면 파일 이름과 클래스 이름이 어긋난다.

이름을 왜 이렇게까지 신경 쓸까?

> **시그니처** — 클래스 · 함수 · 변수의 이름. ==과제는 코드 봇이 이 이름으로 찾아서 채점할 예정이다. 한 글자라도 다르면 못 찾는다.==

> 멈춤 — `BirdMove` 와 `Birdmove` 는 같은 이름일까?

> **대소문자** — ==컴퓨터에게 `A` 와 `a` 는 다른 글자다.== 그래서 `BirdMove` 와 `Birdmove` 는 다른 이름이다. 왜 그런지는 맨 아래 「더 알고 싶으면」.

---

## 이름 짓는 규칙

==다음 시간부터 변수를 계속 만든다. 이름을 어떻게 지을지 먼저 정한다.==

띄어쓰기를 못 쓰니까 **대문자로 단어를 구분한다.**

| 무엇 | 규칙 | 예 |
|---|---|---|
| 클래스 | 대문자로 시작, 단어마다 대문자 | `BirdMove` |
| 함수 | 대문자로 시작 | `Update`, `Start` |
| 변수 | **소문자로** 시작, 다음 단어부터 대문자 | `speed`, `gravitySpeed` |

> **코딩 스탠다드** — 개발자끼리 지키는 이름 짓기 약속. ==지키면 남이 읽기 쉽고, 안 지키면 욕먹는다.==

규칙대로 변수 자리를 하나 만들어 본다. 값은 다음 시간에 넣는다.

```csharp 전
public class BirdMove : MonoBehaviour
{
    void Update()
    {

    }
}
```
```csharp 후
public class BirdMove : MonoBehaviour
{
    float speed;

    void Update()
    {

    }
}
```

> 멈춤 — `Birdmove`, `birdMove`, `BirdMove`. 클래스 이름으로 맞는 것은? 변수 이름으로 맞는 것은?

==클래스라면 `BirdMove`, 변수라면 `birdMove`.== `Birdmove` 는 둘 다 아니다.

## 기획서를 코드 맨 위에 붙인다

==기획서의 플레이어 부분을 `BirdMove.cs` 맨 위에 붙인다.== 다음 시간부터 이걸 한 줄씩 코드로 바꾼다.

플레이어 부분을 복사해 맨 위에 붙여 넣어 보자. ==빨간 줄이 잔뜩 생긴다.== 컴퓨터가 한글 문장을 코드로 읽으려 해서다. **컴퓨터가 읽지 않고 넘어가게 하는 방법이 필요하다.**

> **주석** — ==`//` 뒤는 컴퓨터가 읽지 않는다.== 사람이 읽으라고 적는 메모다.

붙인 줄을 드래그로 고르고 **Ctrl + K, Ctrl + C** — 한 번에 주석이 된다. 풀 때는 **Ctrl + K, Ctrl + U**. 이 단축키도 맨 위에 같이 적어 둔다.

```csharp 전
플레이어
기본적인 이동 로직
오른쪽으로 계속 나아감.
중력으로 인해서 계속 아래로 떨어짐
스페이스를 통해 점프
위 방향으로 스페이스를 눌렀을때 점프를 한다.
```
```csharp 후
// 플레이어
// 기본적인 이동 로직
// 오른쪽으로 계속 나아감.
// 중력으로 인해서 계속 아래로 떨어짐
// 스페이스를 통해 점프
// 위 방향으로 스페이스를 눌렀을때 점프를 한다.
```

파일 전체는 이렇게 된다.

```csharp
using UnityEngine;
using UnityEngine.InputSystem;
// 일괄 주석 컨트롤 + K , 컨트롤 + C
// 일괄 주석 컨트롤 + K , 컨트롤 + U

// 플레이어
// 기본적인 이동 로직
// 오른쪽으로 계속 나아감.
// 중력으로 인해서 계속 아래로 떨어짐
// 스페이스를 통해 점프
// 위 방향으로 스페이스를 눌렀을때 점프를 한다.

public class BirdMove : MonoBehaviour
{
    float speed;

    void Update()
    {

    }
}
```

`using UnityEngine.InputSystem;` 은 지난 시간에 적어 둔 줄이다. 무슨 뜻인지는 점프를 만들 때 나온다.

**왜 맨 위에 적어 두나.** 코딩을 하다 보면 「내가 뭘 만들고 있었지?」 가 정말 자주 온다. ==맨 위에 만들 것을 적어 두고, 한 줄씩 보면서 만든다.== 그게 오히려 빠르다.

다음 시간부터는 이 기획을 카드로 보여 주며, 어디까지 만들었는지 표시한다.

```기획서
플레이어 — 기본적인 이동 로직
· 1. 오른쪽으로 계속 나아감
· 2. 중력으로 인해서 계속 아래로 떨어짐
· 3. 스페이스를 통해 점프
    위 방향으로 스페이스를 눌렀을때 점프를 한다.
```

**Play.** 아직 아무 일도 안 일어난다. ==Console 에 빨간 에러가 없으면 정상이다.==

## 더 알고 싶으면 — 왜 대문자와 소문자가 다른 글자인가

==컴퓨터 안에서 글자는 전부 숫자다.== 글자마다 번호가 정해져 있고, 그 표를 **유니코드** 라고 한다. 영어 알파벳 부분은 옛날 **아스키 코드** 표와 같다.

| 글자 | 번호 |
|---|---|
| `A` | 65 |
| `B` | 66 |
| `a` | 97 |
| `b` | 98 |

`A` 는 65, `a` 는 97. 컴퓨터에게는 아예 다른 숫자라서 다른 글자다.
