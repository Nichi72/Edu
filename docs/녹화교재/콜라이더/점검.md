## 2. 영상 내용을 우리 기획서에 대 보면

우리 기획서(01 의 플래피 버드)에서 Collider 가 필요한 줄은 둘이다.

```
게임오버 조건
  파이프에 닿으면 게임 오버
  땅에 닿으면 게임 오버
스코어
  파이프의 사이를 지나면 점수가 1점씩 오른다.
```

**필요에 의해서 배운다** 로 거르면 이렇게 된다.

| 영상 내용 | 영상 | 기획서에 필요한가 | 초안에서 |
|---|---|---|---|
| Collider 가 뭔지 · 초록 선 | V1 · V2 | 필요 — 새가 왜 땅에 서 있나 | **04** 필요한 것 1 |
| OnCollisionEnter | V1 · V2 | 필요 — 닿으면 게임 오버 | **04** 필요한 것 2 |
| 둘 중 하나는 Rigidbody | V2 | 필요 — 파이프엔 Rigidbody 가 없는데 되는 이유 | **04** 파이프 절 |
| Is Trigger | V1 · V2 | 필요 — 지나간 걸 알아야 점수 | **05** 필요한 것 1 |
| OnTriggerEnter · Collision 과 Collider 차이 | V1 · V2 | 필요 | **05** 필요한 것 2 |
| Stay · Exit | V1 · V2 | 필요 없음 — Enter 만 쓴다 | 04 에 한 줄 · 개념 페이지 |
| Collider 종류 · Center · Size · Edit Collider | V1 · V2 | 필요 없음 — 큐브뿐 | 04 에 한 줄 · 개념 페이지 |
| CompareTag · Tag | V1 | **필요 없음** — 무엇에 부딪혀도 게임 오버, Trigger 는 ScoreZone 뿐 | 개념 페이지 |
| GetComponent 로 상대 컴포넌트 | V1 · V2 | 필요 없음 | 개념 페이지 |
| 레이어 충돌 매트릭스 | V3 | **필요 없음** — 안 부딪혀야 할 짝이 없다 | 개념 페이지 |
| Physics Material | V1 · V2 | 필요 없음 | 개념 페이지 |
| Constraints Freeze Rotation | V1 | 애매 — 게임 오버가 닿는 순간 멈추게 하니 굴러갈 틈이 없다 | 뺐다 |
| Physics Debug 창 | V1 | 필요 없음 | 개념 페이지 한 줄 |

**영상 시간의 절반 이상(Tag · 레이어 · Physics Material · Stay/Exit)이 우리 기획서에는 필요가 없다.** 그래서 본문은 짧고, 나머지는 개념 페이지로 갔다.

## 3. 영상과 우리 프로젝트가 다른 곳

| 영상 | 우리 | 초안에서 |
|---|---|---|
| V1 `Input.GetAxis` (옛 Input Manager) | Input System (`Keyboard.current`) | 영상 코드를 쓰지 않음 |
| V1 Rigidbody 가 있는데 `transform.position +=` 로 움직임 | 03 에서 Translate → `linearVelocity` 로 갈아탔다 | 쓰지 않음. 03 의 이유와 어긋난다 |
| V1 `[SerializeField] private` | 02 부터 `public` | `public` |
| 영상은 Unity 2019 · 2022 | Unity 6.3 (6000.3.10f1) | 메뉴 이름이 다를 수 있다 → 아래 「Unity 에서 확인할 것」 |
| V3 「사용자 레이어 24개」 | 최근 버전은 3 · 6 · 7 번도 쓸 수 있는 것으로 안다 | 숫자를 쓰지 않음 |
| V2 Stay 가 안 찍히는 이유를 말하지 않음 | Rigidbody 가 잠들면(sleep) Stay 가 안 불린다 | 개념 페이지에 더함 |

영상에 틀린 설명은 없었다. V1 의 「감지에는 Rigidbody 필요」 는 V2 처럼 「**둘 중 하나**」 가 정확하다.

## 5. 정할 것

1. **어디에 붙일까.** 1024 수업 03 다음(04 · 05)으로 썼다. 다른 묶음(예: 다른 게임, 단독 「콜라이더」 수업)이면 기획서부터 다시 잡아야 한다
2. **챕터 수.** 기획서 덩어리대로 04 게임오버 · 05 스코어 둘로 나눴다. 한 챕터로 합칠지
3. **파이프 차례.** 기획서 순서는 파이프 → 게임오버 → 스코어다. 초안은 파이프 생성 챕터보다 **먼저** 오고, 파이프를 손으로 놓는다. 파이프 챕터를 먼저 할지
4. **게임 오버가 하는 일.** `Debug.Log` + `Time.timeScale = 0` (모두 멈춤). 다른 안: 새만 사라지기(`Destroy`), 로그만 찍기
5. **코드 위치.** 새 스크립트 없이 `BirdMoveByRid` 에 더했다. 이름이 「Move」 라 어색하면 새 스크립트(예: `BirdHit`)로
6. **Tag · 레이어를 본문에 넣을까.** 기획서에는 필요가 없어서 개념 페이지로 뺐다. 영상 V3(레이어)은 통째로 개념 페이지에만 있다. 꼭 가르치고 싶으면 필요가 생기는 장면을 만들어야 한다 (예: 「땅에 닿으면 다른 말 찍기」 는 억지스럽다)
7. **점수 올리기 문법.** `score = score + 1;` 로 썼다. `score += 1;` 이나 `score++;` 을 쓰시는지
8. **if 정리와 어긋나는 곳.** `1024수업/개념_if.md` 에 「땅에 닿으면 게임 오버를 만들 때 `if(transform.position.y < -4)` 같은 조건을 쓰게 된다」 고 써 두었다. 초안은 Collider 로 한다. 개념_if 의 그 문장을 고칠지
9. **파이프 · ScoreZone 좌표.** 저장소 SampleScene(cp-06) 기준이다 (Ground y −4.5, Bird x −3). 1024 수업 씬과 다르면 알려 주시면 맞춘다

## Unity 에서 확인할 것

초안에 쓰기 전에 Unity 6.3 에서 눈으로 봐야 할 것. 지금 프로젝트 씬은 건드리지 않았다.

- `Time.timeScale = 0` 으로 멈춘 뒤 Play 를 껐다 켜면 1 로 돌아오는지
- `OnTriggerEnter(Collision other)` 처럼 타입을 틀렸을 때 Console 문구 (05 「안 되면」 에 썼다)
- 메뉴 이름 — Physics Debugger, Create > Physics Material, Project Settings > Physics 안의 Layer Collision Matrix 위치
- 1024 수업 씬의 Ground 가 Cube 인지 Plane 인지
