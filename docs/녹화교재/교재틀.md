## 철칙 — 필요에 의해서 배운다

**목표(기획서의 한 줄)가 먼저다.** 그걸 이루는 데 필요한 기능 · 변수 · 함수 · 개념을 **그때** 배운다. 필요해지기 전에는 가르치지 않는다.

- `public` 은 변수를 만들자마자 나오지 않는다. 떨어지는 속도를 여러 번 맞추다 「코드를 열지 않고 바꾸는 방법이 필요하다」 에서 나온다
- 주석은 기획서를 코드에 그대로 붙였다가 빨간 줄을 본 뒤에 나온다

## 읽는 사람

- 교재를 화면에 띄워 놓고 수업한다. **강사가 치는 코드 = 교재의 코드.** 이름은 철자 · 대소문자까지 같다
- 학생은 글을 잘 안 읽는다. 문장은 짧게. 꼭 읽어야 할 것은 형광펜
- 수업과 교재는 호흡이 다르다. 수업 순서와 말을 그대로 옮기지 않는다. **순서를 바꿔도 되고, 빼도 된다**

## 챕터 뼈대

| 차례 | 무엇 | 규칙 |
|---|---|---|
| 제목 | `# 02. 플레이어 — 기본적인 이동 로직` | 기획서의 덩어리 |
| 이번 시간에 만드는 것 | 「Play 를 누르면 이렇게 된다.」 + 번호 목록 | **결과로 쓴다.** 끝나면 게임이 어떻게 되는지. 「세 줄을 코드로 옮긴다」 같은 작업 설명은 안 된다 |
| 이번에 배우는 말 | 이름만 한 줄, 각 절로 링크 | 설명은 여기 쓰지 않는다. 처음 겪는 절에서 |
| 이름 표 | 이름 · 무엇 · 값 | 이번에 정해지는 이름. 「철자와 대소문자까지 이대로 쓴다」 |
| 시작하기 전에 | 체크리스트 | 앞 챕터를 끝낸 상태 |
| 절 | 기획서 한 줄 = 절 하나 | 아래 「절 하나」 |
| 확인하기 | 체크리스트 | Play 해서 눈으로 볼 것 |
| 안 되면 | 증상 → 원인 | 실제로 막힌 것만 |
| 답 | 끝났을 때의 코드 전체 | 맨 뒤. 첫 줄은 「여기까지 스스로 해봤다면 봐도 된다.」 |

앞 챕터의 문제를 고치는 챕터는 진단 절을 먼저 둔다. 예: ch03 「왜 점프 같지 않을까」.
깊은 곁가지는 맨 끝 「더 알고 싶으면 — …」 절로 뺀다. 예: ch01 의 유니코드.

## 절 하나

**절 제목 = 기획서 줄 그대로.** 괄호 설명은 붙이지 않는다. 예: `## 오른쪽으로 계속 나아감`

1. **기획서 카드.** 기획서 전체를 보여 주고 지금 줄은 ▶, 끝낸 줄은 ✓ 로 표시한다
2. **만들 것 한 줄.** `==Play 하면 새가 오른쪽으로 계속 날아가게 만든다.==` 지금 상태를 바로 옆에 둔다
3. **필요한 것.** 「이걸 하려면 두 가지가 필요하다」. 길면 `### 필요한 것 1 — …` 으로 나눈다
4. **해 본다.** 코드. 바뀌는 코드는 전·후 비교로 보여 준다
5. **▶ Play.** 화면에서 무엇이 보이는지
6. **짚기.** 방금 한 것에 이름을 붙인다. `> **하드코딩** — …` 상자이고, 상자 제목이 용어 이름이다

짚기는 이 순서다. **해 본다 → 결과를 본다 → 불편하거나 이상한 점 → 그것에 이름을 붙인다.**
예: `* 5` 를 친다 → Play → 「이 5 가 뭐지? 석 달 뒤엔 모른다」 → 그걸 하드코딩이라 부른다 → `speed` 로 바꾼다

- **멈춤.** `> 멈춤 — 질문` 을 두고 바로 다음 줄에 답을 형광펜으로 쓴다. 강사가 멈추는 자리다
- **다음 시간 질문.** 챕터의 마지막 절 끝에 `> **다음 시간 질문** — …` 을 둔다

## 깊이

- **「이런 게 있다」 수준.** 쓰는 법 한 줄만 쓴다. 예: `Keyboard`
- **중요한 개념.** 챕터에서는 쓰는 법만 쓰고, 깊은 건 개념 정리 페이지로 링크한다. 예: `개념_if.md` → `concept-if.html`. 개념 페이지는 챕터를 끝내는 데 없어도 되는 것이어야 한다
- **같은 개념을 두 번 설명하지 않는다.** 앞에서 했으면 「01 의 이름 규칙이다」 처럼 가리킨다

## 강조

| 표시 | 어디에 | 원고 |
|---|---|---|
| 형광펜 (노란 바탕 + 굵게) | 꼭 읽어야 하는 **한 문장**. 절의 만들 것 · 짚기 상자의 핵심 · 놓치면 막히는 주의 · 멈춤의 답 · 안 되면의 원인 | `==…==` |
| ▶ Play | Play 해서 보는 곳 | `**Play.**` |
| 굵게 | 보조 강조 | `**…**` |

- **형광펜만 따라 읽어도 흐름이 이어져야 한다**
- 한 절에 몰리면 굵게로 낮춘다. 챕터당 스무 곳 안팎이다 (ch01 19 · ch02 21 · ch03 25)
- 형광펜 안에 `==` 연산자가 들어가면 깨진다. 그런 문장은 굵게로 쓴다

## 기획서 카드

````
```기획서
플레이어 — 기본적인 이동 로직
✓ 1. 오른쪽으로 계속 나아감
▶ 2. 중력으로 인해서 계속 아래로 떨어짐
· 3. 스페이스를 통해 점프
    위 방향으로 스페이스를 눌렀을때 점프를 한다.
```
````

✓ 끝낸 줄 · ▶ 지금 줄 · `·` 아직 안 한 줄. 들여 쓴 줄은 바로 위 줄의 설명이다.

## 바뀐 코드 — 전·후 나란히

````
```csharp 전
    float speed;
```
```csharp 후
    float speed = 5;
```
````

- 두 블록 사이에 다른 글을 두지 않는다. 새 줄은 초록, 지운 줄은 빨강 취소선, 바뀐 칸만 따로 강조된다
- 바뀐 곳 둘레만 자른다. 나머지는 `// … 1 · 2 는 그대로 …` 로 줄인다
- 주석 띄어쓰기 같은 사소한 차이는 양쪽을 맞추거나 주석을 뺀다. 그대로 두면 핵심이 묻힌다
- 파일이 다르면 이름을 적는다. ```` ```csharp 전 BirdMove.cs ```` / ```` ```csharp 후 BirdMoveByRid.cs ````

## 페이지에 넣지 않는 것

- 「알아야 할 것」 용어 표. 용어 설명을 앞에 몰아 두는 것
- 영상 시각
- 교수용 블록. 상태 · 분량 · 재료 같은 만드는 과정의 정보는 md 머리말과 꼬리 주석에만 둔다. 페이지에는 찍히지 않는다
- 수업 진행용 이야기. 예: VS Code 테마 바꾸기

수강생은 아티팩트 「플래피 버드로 배우는 Unity」 (https://claude.ai/artifact/5beVBe3LuF4fPCRWLMU96t) 로 본다. 비밀번호로 잠근 한 파일이다.

3. 같은 아티팩트 주소에 덮어 발행한다. 공유 링크가 옛 판에 고정돼 있으면 아티팩트의 Share 메뉴에서 최신 판으로 바꾼다

## 만드는 차례

1. 수업을 녹화한다. OBS 와 수업 기록기를 같이 켠다
2. 재료로 만든다. 전사하고, 시각을 맞추고, 실제로 가르친 순서를 정리한다. **여기서 멈추고 강사가 확인한다**
3. 이 틀로 원고를 쓰고 빌드한다
4. 강사가 보고 피드백한다 → 고친다. 바뀐 규칙은 이 파일에 반영한다
